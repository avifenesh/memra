# H100

NVIDIA's H100 (Hopper, compute capability 9.0): a source-build lane with its own kernels, flags and
ledger. Its prebuilt and CI cell were retired on 2026-09-02, and its standing battery with them.

| | |
|---|---|
| **Build target** | `sm_90a`, auto-detected on an H100 (`MEMRA_CUDA_ARCH=90a` forces it); Hopper promotions are compile-gated behind `memra_hopper_mma`, so the `sm_120a` build stays byte-identical |
| **Prebuilt** | no (retired 2026-09-02) |
| **Push gate** | no (`tools/change-impact.toml`); no CI cell compiles `90a` |
| **Maintained** | no: the target is not push-gated, so `tools/change_impact.py` counts an H100 as an unmaintained device class; its gates run on Hopper hardware directly |

## Device-keyed defaults

H100 does not inherit Blackwell defaults. Its flags are in [FLAGS.md](../FLAGS.md) section 7; for
example the Q8_0 and K-quant split-plane decode mirrors (`MEMRA_Q8RP`, `MEMRA_KQRP`) are on by
default on the Hopper lane.

## Models measured here

The H100 board in [PERFORMANCE.md](../PERFORMANCE.md) (generated from
`research/tune-data/current-board.json`) lists each model, its artifact and its measured ratio.
The lane's evidence ledger is [ARCHITECTURE-H100.md](../../ARCHITECTURE-H100.md), append-only.

## Limits

- With the standing battery (`validate-h100.sh`) retired, run these on Hopper directly:
  `kernel-check` with its config pins, `decode-batch-gate` (config and strict), `decode-dc-gate`,
  `graph-decode-gate` and `graph-session-gate`.
- Compare performance only interleaved on the same box: cross-run and cross-day comparisons drift.
- No pack record names an H100 topology.
