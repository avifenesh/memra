# B200

| | Recommended use |
|---|---|
| **Role** | Runtime-qualified source backend; no published prebuilt yet |
| **Build** | `sm_100a`, auto-detected from B200 compute capability 10.0 |
| **Best fit** | NVFP4 serving and B200 backend development |
| **Start with** | Qwen3.5-9B NVFP4 on the default W4A8 path |

B200 support is artifact-specific. The 2026-09-01 qualification used one NVIDIA B200, CUDA
13.1.115, driver 580.173.02, and commit `69a2eb3684e1`; the sealed receipts are under
`research/b200-kernel-twins-dry-20260901/receipts/`.

- **NVFP4:** `NativeQualified` on the pinned Qwen3.5-9B GGUF used by the receipt. Default W4A8
  passed the model manifest, K=1..8, sampled serving, concurrency 4, admission, and rollback gates.
  F8F4 stays opt-in. Raw-layout W4A4 is correct but needs both `MEMRA_RP=0 MEMRA_MMQ=1` and
  measured 4,758.6 versus 9,134.3 tok/s for raw W4A8 at pp1483, so it is not a default candidate.
- **Block FP8:** `NativeReference` only. The explicit B200 twin passed the nine-shape synthetic
  oracle, K=1..8, sampled serving, and concurrency 2 on pinned `Qwen/Qwen3.8-27B-FP8`, but measured
  530.9 versus 3,071.1 prefill tok/s for the established fallback and worse teacher-forced NLL.
  `MEMRA_FP8_MMQ=1` therefore remains explicit on B200.

Check [installation](../INSTALLATION.md), [models](../MODELS.md), and the exact receipt scope before
generalizing these results to another checkpoint or topology.
