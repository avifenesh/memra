## S08: qwen4exp_gpu.rs (qwen4_exp eager GPU arm)

`crates/memra-engine/src/qwen4exp_gpu.rs` (21,138 lines) holds the native GPU implementation of `qwen4_exp` (Qwen3.8-Flash-Next): a 4-stream gated-residual trunk, interleaved GDN and QSA micro-block-sparse attention layers, a 512-expert softmax MoE with a gated shared expert, PLE n-gram embeddings with a host-resident table, a YaRN rope, and an MTP draft block. The engine type is `Qwen4ExpGpu` (L426).

### Reach

No serving path calls this module. Its callers outside the file are the gate and probe binaries `qwen4exp_real_gate` (bin L34), `qwen4exp_gpu_gate` (bin L36), `sel_shape_probe` and `moe_union_probe`, plus a memra-tier test that `include_str!`s the file (tier `tests/bank/main.rs:1110`). `memra-server`, `HybridModel`, `decode.rs` and `hybrid.rs` have no reference to it. The impact of a change here is therefore {qwen4_exp} x {the gate programs}: plain, prime, chunked_prefill, graph, mtp, tp, ep and spill (host bf16 banks, the PLE rows tier). It reaches no http_api, batch or prefix_cache cell. There is no `cfg!`, built-arch or SM-count predicate in the file, and every kernel it launches is live in all six build variants, so devices stay `*`. Formats: BF16/F32 dense (`dequant_float` L16050), BF16 or modelopt-NVFP4 expert banks (`read_bank_tensor` L16092), and a q8_0 K / q5_1 V QSA cache.

The reverse direction is wide. The file uses engine-wide doors and helpers: `Engine::norm_ilp_on` and `crate::rms_block` (L4989), `linear_device_into` and `bf16_to_f32`. It also uses shared `cu/kernels.cu`. Changes there reach qwen4_exp.

### Hot paths

- **Single-card forward** `forward_with` (L10632) serves `prefill`, `prefill_extend` (chunked, head skip L10929), `decode_step` and verify chunks. Per layer it runs PLE, the hyper read gate, the mixer (QSA or GDN), the hyper write, the MoE and the write again.
- **Decode graphs** (`forward_graphs_tail` L11715) engage when t==1, the graph, ws and hc seams are on, no profiler is running and verify is not armed (L10685). GDN layers without PLE and NVFP4 MoE tails replay. QSA layers stay eager because selection runs on the host.
- **Hyper gate.** The diet 3-launch program runs at t==1 and on verify-exact chunks (L11077), with MT stages at 2..=12 (L11098). Plain prefill takes the fused chain (L11187+). `hc=0` takes the legacy chain (L11066).
- **MoE** `moe_forward` (L12832). The device router (L12877) feeds the grouped NVFP4 selected-expert program (L12951), which also merges verify columns (L12978). The DeviceBf16 path is the MTP draft bank (L13276). The per-expert executor (L13457) handles all-rows prefill and dequantizes F32/NVFP4/HostBf16/DeviceBf16 banks. The kernel variant (selgroup AUTO, v3, v2, v1) is picked at runtime (L6076, L6161).
- **QSA.** Indexer scoring runs on device with a device top-k (`idxsel`, L3556). The block-list attention is the only read path for the default quantized KV (L12368). The masked SDPA kernel is reached only with `kvq=0` (L12434).
- **GDN.** The step-scan twin runs at t==1 (L12630). Fused norm+gate is on by default (L12791). Verify segment graphs are default OFF (L12707).
- **MTP spec** `spec_generate_ext` (L15125): greedy and sampled targets (L15598), chunked co-prefill (L15261), adaptive K and dynk (L15761), verify rewind (L14916), FR-Spec trim and deferred chain (L10165, L10253).
- **TP2** (L17513-L20551): trunk head halves plus expert-half split, `MEMRA_Q4E_EP_MAP` placement (L2540), per-rank segment graphs (L18589) and red-arm defects (L2786).

### Effects and doors

Almost every arm is a process-global seam with a default, flipped only through `MEMRA_Q4E_SEAMS` (L3036), which only the gate bins call. Default-ON numeric-class arms reached by a naked gate run are trunk bf16, hcdiet, gdnstep, selgroup AUTO, routerdev, kvq and idxq q8. Each changes accumulation order, so its effect is numeric. Default-OFF doors are kvhoist, poolT, vgraph, vfuse, the EP map, the TP2 red arms, the rows tier, the peer KV cap and the trace doors. The gate and probe functions (L6275-L9471, L21021) only produce verdicts, so their effect is observability. `cfg(test)` code runs from L20554.

### Findings

1. **Decoupling (medium).** 45 kernels launched only from this file live in the shared `cu/kernels.cu`. Under the repo's ".cu change = full battery" rule, any edit to them pulls every family into the impact set. Moving them to `cu/qwen4exp.cu` limits that impact to qwen4_exp.
2. **Reusable code.** `launch_push` (L17265) duplicates `tp.rs::launch_tp2_peer_push`, and `q4e_push_f32` is already a shared TP2 join kernel. `tp2_enable_p2p` (L17281) reimplements `configure_native_p2p`.
3. **Mergeable code.** The bf16w `_off`/`_off_into` launchers and the GDN `_at` launchers copy their base launchers on views.
4. **Gate-seam bugs.** `longatt=auto` arms Force (L3001). An unknown `idxq` value silently selects F32 (L2372).
5. **Dead code.** `qsa_indexer_mask` (with a false comment, L18389), `kv_hoist_is_on`, `pool_t_is_on`, `MtpDraftState::rows`, `mtp_on_dev1` and `spec_disarm` have no callers. `is_even` is called only from tests.
6. **Stale docs.** The TP2 "graphs stay off" doc is wrong (L18499 vs L18589). The verify_mt doc says prefill is untouched, but the mt kernel runs on any 2..=12-row forward (L1843 vs L6031). One line reference is stale (L1555).
7. **Stale flags.** The kvhoist, poolT and vgraph FLAGS rows have no decide-by date.
