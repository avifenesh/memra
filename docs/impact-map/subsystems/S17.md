# worker.rs, first half (lines 1-22673): admission policy, prefix cache and host KV tier

## What the slice does
This half of `crates/memra-server/src/worker.rs` contains no forward pass. It holds the policy and state the scheduler (`run`, `admit`, `prefill_tick`, `step_session`, all in the second half) uses to choose a route per request:

- **Prefill sizing:** `prefill_tick_take` (worker.rs:222), `interactive_prefill_budget` (:183), the carried and concat prime predicates (:248, :270).
- **Spec policy:** the K choice `choose_spec_k` (:6749), gate thresholds (:6653), `serve_spec_enabled` (:6541), sampled-restore guards (:336, :569), the DFlash cold-prefix trade (:696-867) and the gemma/glm5/dspark sampling configs (:1055-1120).
- **Device prefix cache:** budget derivation (:4709), grid-aligned capture boundaries (:3893-4140), `PrefixCache` lookup, insert and eviction (:8706-9506).
- **Whole-session reuse pools:** parking, compaction, exact and grid-rewind resume (:2549-3555).
- **Admission memory:** `AdmissionCostModel` (:2780), `admission_reserve` (:6941), VMM helpers (:7315), driver headroom and reclaim settle (:7890-8069).
- **Fault boundaries and injection doors** (:8159-8507).
- **Pinned-host KV tier** (`HostPrefixCache` and its contract machinery, :9536-21391) and the **cross-deploy handoff** (:21393-22673).

## Reach
DeepSeek-V4 requests leave at `handle_cmd` for their own thread (worker.rs:33085). Every cache, spec and admission item here therefore reaches only HybridModel families. Only the shared types (`Request`, `Event`, `EngineError`) and the boot refusals reach every family. Hence the file default is `*`; regions narrow it.

## Hot default paths, by route
- **prime / chunked_prefill (all HybridModel families):** `prefill_tick_take`, the solo widening and `grid_align_boundary_within` (:4031) decide where prime calls split. For GDN trunks (qwen35, qwen35_moe, qwen4_exp) an off-grid split is a second numeric program, so these regions are `numeric`. Attention-only plans are split-invariant (doc at :4002), so for them the effect is speed and cache depth.
- **prefix_cache (default ON in batched mode):** the derived budget is two served-context entries clamped by boot free VRAM (:4766). This is the only device input in the slice: the same model on a 24 GB or a 96 GB card holds a different number of entries, which changes hit rate and which entry restores. Capture boundaries (`seed_capture_boundary` :4116, `hit_lcp_snapshot_boundary` :4056) are numeric for GDN plans. `should_probe_prefix_cache` (:893) is reached on every admission.
- **mtp (qwen35, qwen35_moe, step35, hy3) and glm5_spec (glm5_next):** `choose_spec_k` sets K: 0 above LOW, 2 on cached-long prompts (5 for rank-trimmed heads), 3 otherwise. The demand signal is the HTTP in-flight gauge, a global OnceLock written by lib.rs (:491-563).
- **dflash (qwen35, qwen35_moe, qwen4_exp):** the whole `DsparkColdPrefixAdmission` block sits behind `MEMRA_DSPARK_SPEC=1`, so no default cell reaches it.
- **gemma_spec (gemma4_dense, gemma4_moe):** armed only when `MEMRA_DRAFT` is set (:6520).

## Default-OFF mass
Most of the slice's lines are reached by no naked launch:
- the host tier: `MEMRA_KV_HOST_MB` defaults to 0 (:5648), and `armed()` (:10321) gates every demote, promote and capture;
- the contracts machinery: `MEMRA_KV_HOST_CONTRACTS` (:4921);
- the handoff: `MEMRA_KV_HOST_HANDOFF`;
- the VMM allocator: `MEMRA_KV_ALLOCATOR` (:7345);
- park compaction, exact resume and grid rewind;
- the partial-restore, latent-prefix, hyper-suffix-prime and glm5-TP-prefix doors.

The only default-reached lines inside the host region are the early-return gates, such as the OnTick answer at :19181.

## Device-specific parts
There are no arch, SM or card-class predicates in this half; the arch-scatter candidate belongs to the second half. Device dependence enters only through free-VRAM readings:
- the derived prefix-cache budget;
- the driver-headroom trim (2048 MiB floor, :7890);
- the kv-flex grant.

These are `memory` and `policy` effects that differ per card, so devices stay `*`.

## Why the impact set is wide
1. The host tier and handoff (about 13k lines, all default OFF) share a file with the default scheduler, so a path-based gate maps any edit there to every cell. Moving them into `worker/host_tier.rs` would cut every default cell from those edits.
2. Prefix-cache and boundary code is shared by all 14 HybridModel families and by the prime, batch and spec routes, so it is correctly wide.

## Top findings
- **Spec-gate timing bug (medium).** `log_spec_gate_policy()` runs at :26076, before model load, and freezes `spec_gate_thresholds()`. `MEMRA_PARALLEL=auto` sets `MEMRA_PP_STAGES` only during load (hybrid.rs:856), so an auto-placed cross-device PP-2 step35 or hy3 deployment keeps the single-card LOW=2. It admits MTP spec where every PP-2 cell measured a loss.
- **KV flex defeated (low).** `prefix_insert_from_session` preflights with the floor budget (:24291) while the insert uses floor plus grant (:5943), so flex borrowing never survives a publish.
- **Stale doors.** These are past their decide-by dates with no decision: `MEMRA_KV_HOST_CONTRACTS` (2026-10-05), `MEMRA_RESUME_EXACT`, `MEMRA_RESUME_GRID_REWIND`, `MEMRA_SPEC_BUDGET_CLAMP`, `MEMRA_KV_PARK_COMPACT`, `MEMRA_ADMIT_RECLAIM_OFFTICK`, `MEMRA_BATCH_OOM_RECOVER`, `MEMRA_ADMIT_W_RELEASE` and `MEMRA_KV_ALLOCATOR`. `MEMRA_PREFIX_PARTIAL_RESTORE` survives a NO-GO receipt.
- **Hygiene.** About ten doc blocks are attached to the wrong function, and the module header still describes the retired one-token round-robin. The three SpecSampling builders and the two resume programs are mergeable.
