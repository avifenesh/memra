## S21: host crates (tokenizer, sampling, kv, runtime, lanes, reference, validate, net-guard, probe)

Most of this slice is host code that every request crosses, plus the reference executor, which is the qualification oracle and does not serve. The impact rule follows from that: tokenizer, sampling and lanes changes are device-independent (one CPU suite qualifies them) but family-wide unless a dialect predicate narrows them. memra-kv and memra-runtime run on the GPU and reach every device.

### Tokenizer (`memra-tokenizer`)
Every prompt goes through `Tokenizer::encode_special` (lib.rs:1073), so the file default is all families and routes, numeric.
- **Pre-tokenizer.** `PreSplit::resolve_with` (lib.rs:172-206) picks the split from artifact metadata, not from the pack.
  - SPM arm (lib.rs:1141-1173): gemma4 only, because `spm_style` comes from `tokenizer.ggml.model == "gemma4"` (lib.rs:334).
  - `split_qwen35` (unicode.rs:189): Qwen3.5+ checkpoints.
  - `split_qwen2_with_digit_limit` (unicode.rs:419-591): one state machine shared by the qwen2 split (Qwen3) and the glm4 split (GLM-5.x, DictaLM), so an edit reaches both.
  - `split_deepseek_v3` (unicode.rs:744): Hy3, Step-3.7 and DSv4.
  - These narrowings are artifact-keyed, so I marked them conservative.
- **Chat templates.** `chat.rs` dispatches on substrings of the template string (dynamic edge). The dialect arms are family-local: MiMo 195/524, Hy3 209/588, Step35 217/554, DSv4 165/235/539, GLM5 260/570, gemma4 277/608/622.
  - The ChatML fallback (280-325, 640-826) serves every unrecognized family, so it stays `*`.
  - The Qwen3.8 effort ladder (418-438, 644-708, 766) is template-keyed.
- **Detokenizers.** `detokenize.rs` is reached only from Whisper/RNNT code.

### Sampling (`memra-sampling`)
`Sampler::sample` (lib.rs:341) is the host chain for every family; its arms are request config, not family. `apply_penalties_dense` is also the bit oracle the device penalty kernels are gated against (lib.rs:459-464), so a change there moves spec-route numerics too. The PrefixRadix nucleus ordering (lib.rs:597-733) is built only by `for_glm5_plain_tp2` (worker.rs:34916): glm5_next on the plain TP route. It is claimed ordering-only; I labeled it speed plus numeric, conservative. The `spec_stop.rs` p-min stop arm is behind `MEMRA_SPEC_PMIN` (default 0) and reaches the MTP and glm5 spec loops.

### KV cache (`memra-kv`, re-exported as `memra_engine::cache`)
`Cache::new_inner` (lib.rs:3066-3265) allocates per StatePlan:
- full/sliding KV: every attention family, q8_0 K / q5_1 V;
- `Recurrent`: GDN/KDA families;
- `LatentKvCache`: glm5_next and glm_dsa.

Family-keyed doors:
- **Gemma fp8 KV.** `gkv_on` is default ON. `wkv_on` defaults ON unless `MEMRA_DRAFT` is set, so a gemma deployment with the drafter configured runs a different KV numeric class (lib.rs:98-119, 2388-2389).
- **Step35 SWA ring.** Armed at step35 load (lib.rs:121-419).
- **DSA indexer tail ring.** Default ON, glm5_next and glm_dsa (lib.rs:190-290, 3215).
- **Latent snapshot/restore.** Prefix cache and glm5 spec (628-1313).
- **TP KV transactions.** tp route (1334-2181).
- **VMM on-demand planes.** `MEMRA_KV_ALLOCATOR=vmm`, default off (plane.rs:247-983).
- **Host prefix tier.** `MEMRA_KV_HOST_MB`, default off (tiered/hostprefix.rs).

Admission sizing (`cache_bytes_per_token_for_plan`, `latent_kv_bytes_per_token_for_plan`) is memory/policy. The rest of `tiered/` (Hierarchy, Scheduler, policy, integration) has no installed caller.

### Runtime (`memra-runtime`)
`Gpu::stream()` (lib.rs:193) is the launch stream for the whole engine. `Gpu::new` (263-325) sets the mempool reuse policy that decode determinism depends on, so it is all families, all GPUs, numeric. The PP/TP stream overrides are reached on the pp/tp/ep routes. The rank0 redirect and decode-phase streams sit behind default-off doors.

### Lanes, net-guard, validate, probe
- **Lanes.** Lane policy is admission plus per-lane prefill budgets (lanes lib.rs:131-200). The budgets set chunked-prefill boundaries, so I kept numeric conservatively. `audio_stream.rs` is audio_asr policy only.
- **net-guard.** Classifies image_url fetch addresses (vision route policy).
- **validate.** Gate-only.
- **probe.** An unreferenced spike crate.

### Reference (`memra-reference`)
The oracle for `memra model verify` and the GPU parity gates (routes empty, CPU). Per-family oracle regions: qwen4_exp gated residual/PLE/QSA, hyper-connections, gemma dense/parallel-MoE, MLA/DSA, compressed MLA, GDN, KDA, MoE, DSpark, glm5 vision. Only three things reach serving: `ReferenceTensor/Weights` (the qwen4_exp loader), `hidden_trace` (`MEMRA_HYPER_TRACE`) and some MiMo helpers.

### Where the impact set is wide
- The tokenizer ChatML fallback and the host sampler are genuinely `*`.
- memra-kv lib.rs is one 4k-line file mixing all state kinds. It stays `*` by default, and its regions carry the precision.
- memra-reference is a regular dependency of memra-engine, so a file-level graph ties the oracle to serving. Cutting that (finding) removes every serving cell from oracle edits.

### Top findings
1. The SWA-ring default is a process-global atomic set by step35 load, so a co-loaded gemma4 model gets ring planes its kernels cannot address (memra-kv lib.rs:133; plausible, medium).
2. Decouple memra-reference from memra-engine (Cargo.toml:21).
3. `MEMRA_RANK0_MERGE` has a negative receipt but its door and runtime machinery survive (runtime lib.rs:226).
4. `MEMRA_KV_ALLOCATOR` is past its decide-by date (FLAGS.md:318).
5. Stale docs: hidden_trace claims no arm change, tiered claims no server path, gkv doc.
6. Dead sizing wrappers and tiered scaffolding.
7. `snapshot_plane` can merge into `snapshot_tail` plus `snapshot_plane_at`.
