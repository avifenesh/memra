## S14: quantized matvec and GEMM kernels

**What it is.** These files hold the weight-format arithmetic for every HybridModel family: the m=1 decode matvecs, the batched b2..b16 verify and decode tiers, the MoE expert matvecs, and the m>=16 prefill GEMMs. `qmatvec.cu` (14.5k lines) is a single fatbin. Rust looks its kernels up by name (`Engine::func`). The MMQ/prefill TUs are a static archive called over FFI (`mmq_ffi.rs`, `fp8_ffi.rs`, `f16_ffi.rs`, `cutlass_ffi.rs`). deepseek_v4 never reaches this slice: `is_dsv4_dir` routes it to Dsv4Gpu (`crates/memra-server/src/dsv4_serve.rs:57`), and no static caller chain from these launch sites reaches a dsv4 item.

**Hot paths by route.**
- *plain/graph decode (m=1)*: `qmatvec_{q8_0,q4_K,q5_K,q6_K,nvfp4,q4_0,e4m3,e4m3_blk}_mmvq*` plus the split-plane `_rp` twins (`qmatvec.cu:795-1503, 2858-2976, 8673-10066`).
- *batch, mtp, dflash, glm5_spec verify (m=2..16)*: the batched tiers. `Engine::qmatvec_mmvq_batched` builds the kernel name from qtype, mcols and a variant that `batched_variant` picks from the shape, the rp layout and the SM count (`lib.rs:23950`). The stage-0 graph cannot see these names; see dynamic_edges.
- *prime and chunked_prefill (m>=16)*: the vendored MMQ runs first (`lib.rs:18156`): NVFP4 W4A8, Q8_0, Q4_0, Q4_K/Q5_K, IQ4_XS dense. The hand-rolled int8 `qmatvec_gemm.cu` takes Q6_K, NVFP4 on h100 and shapes MMQ refuses. Under verify-exact scope the threshold moves to MAX, so dflash verify stays on the matvec class.

**Family-specific parts.** Most kernels are keyed by format, not family.
- KDA fused6: glm5_next, behind the default-off `MEMRA_KDA_FUSED_PROJ` (`qmatvec.cu:951-1149`).
- PRE-clamped MoE epilogue pair: glm5_next (`6178-6340`).
- GeLU MoE kernels: gemma4_moe (`7269`, `8481`).
- Fused Q4_0 m=1 and batched: gemma4 (`8743`, `9433`).
- GDN group-4 tuple: qwen35/qwen35_moe/qwen4_exp (`2333`).
- Calibrated A4 prefill: qwen35 27B artifacts only (`mmq_fp4.cu:1248-1663`).
- MLA bf16 strided GEMM: glm_dsa/glm5_next (`f16_prefill.cu:484`).
- Step TP decode-v2 kernels: tp route only (`11428-11765`, `12537-13163`).
- MoE kernels never reach dense families.

**Device-specific parts.**
- PDL sync only on non-portable sm>=90 builds (`qmatvec.cu:18`).
- `build.rs` swaps in fail-closed stubs for mmq_fp4, mmq_nvfp4_w4a8 and mmq_fp8_blk on 89/90a (`build.rs:557-584`).
- 100a: tcgen05 twins behind `MEMRA_MMQ` / `MEMRA_FP8_MMQ`, plus the plain f8f6f4 forms.
- 120a: the mxf4 W4A4 GEMM (`MEMRA_FP4`) and CUTLASS (non-default build).
- 90a: the opt-in wgmma q8_0 GEMM; the Q4_0 MMQ stream-K arm is off there (`mmq_ffi.rs:1924`).
- sm89: every MMQ and int8 GEMM is refused.
- The SM count picks the batched variants, but those are speed-only twins of one numeric program.

**Effect kinds.** Most regions can change output bytes. A different MMQ fold order is a different numeric class, and per AGENTS.md a prefill change also moves acceptance. Speed-only regions are the bit-identical schedule twins: rp mirrors, ILP twins, B200 GEMV v2, r2 doors.

**Where the impact set is wide, and why.**
1. The format kernels serve every family that can ship that format. Packs with `formats: ["*"]` keep family sets at all.
2. The W8 mirror kernels hang off a process-global step37 default inside generic `matvec_bf16_rows_into` (`lib.rs:1577`, `26533`), so they reach every BF16 family.
3. Default-off doors and forced-only variants add code with no default cell. The map should drop those cells using `door.default_reached=false`.

**Top findings.**
- **Load bug (medium).** On h100/sm89 every block-128 FP8 checkpoint fails to load. The stub `memra_fp8_blk_count_nan` returns 2905 and the load path propagates it as an error instead of declining to the Q8_0 floor (`mmq_fp8_blk_stub.cu:32`, `model.rs:1022`).
- **Cross-family numeric bleed (medium).** The step37 serving defaults are process-global, so loading a step35 model reroutes other models' BF16 matvecs through q8_0 mirrors (`lib.rs:1577`).
- **Never-launched twins (medium).** The spill-free compile-time-T tcol twins are never launched; the step TP walk uses the spilling runtime-t kernels (`qmatvec.cu:11627`).
- **Dead or unreachable kernels.** Six kernels sit behind uncalled launchers, the `dual_silu_ilv` door is gone but its kernel remains, and the Q4_0 b16 r2 twins cannot be selected.
- **Overdue doors.** `MEMRA_Q80_BATCH_R2` and `MEMRA_E4M3_BATCH_R2` passed decide-by 2026-09-19. Four default-off doors have no date. `MEMRA_Q8_ROW_ILP`'s b200 default only runs once `MEMRA_B200_GEMV_V2` is also set.
- **Merges.** Five copies of the q8_1 MMQ quantizer and an exact duplicate MMA dot body could move into `mmq_common.cuh` / `mmq_mma_i8.cuh`, which shrinks each fix's blast radius to one cell.
