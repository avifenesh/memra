## memra-server: HTTP waist and the rest of the server (slice S19)

### What the slice does
`lib.rs` (live code 1-12609, tests after) is the request waist that every family goes through. It authenticates, admits, builds a worker `Request` and serializes the result. Every chat-shaped surface goes through one builder, `build_chat_request_with_trace` (lib.rs:8948): `/v1/chat/completions` (lib.rs:11050), `/v1/messages` (anthropic.rs:183 translate), `/v1/responses` (responses_api.rs:152) and the shared core in surfaces.rs:100. `/v1/completions` uses `build_request_with_trace` (lib.rs:8748). The capture surfaces live in embed_api.rs:102.

The rest of the slice is policy and support: admission doors (admit_memory, admit_predict), auth, background jobs, health, metrics and telemetry, route contracts, the VMM KV door (kv_vmm), the host-tier GLM images (worker/host_glm.rs), the grammar engine (constrained.rs), tool-call grammars and parsers (tool_constraint.rs, toolcall.rs) and n-choice fan-out (multi_choice.rs).

### Numeric hot paths (all families)
These are where the server changes output bytes for every family:
- **Sampling.** `SamplingDefaults::resolve` (lib.rs:3807) takes the metadata defaults first, then the caps defaults that only hy3/step35 plans set (lib.rs:3811, worker.rs:26505). `for_mode` (lib.rs:3876) picks a non-thinking arm, and `resolve_sampler_config` (lib.rs:3946) is the single client > vendor > API-default law. `sampler_config` (lib.rs:5136) sets the penalty window and a fresh seed.
- **Think and effort.** `parse_think` (lib.rs:5334) and `canonical_effort_for` (lib.rs:5639) feed both the rendered prompt and the vendor arm choice.
- **Prompt turns and placeholders.** `content_to_text_vision` (lib.rs:4888) renders turns and the vision placeholder runs.
- **Delivered text.** Stop truncation and holdback (lib.rs:11965, 12004; surfaces.rs:652) and the tool/reasoning parsers (toolcall.rs:359) change the bytes the client gets, but not the token ids.

### Family-narrow arms
The caps markers are template-keyed (worker.rs ModelCaps), and they narrow the chat builder per family:
- **glm5_next:** parser lib.rs:9258; max effort tier lib.rs:9017.
- **hy3:** parser lib.rs:9260; stop lib.rs:9327.
- **deepseek_v4:** DSML parser lib.rs:9262; stop lib.rs:9322; max tier.
- **gemma4_dense / gemma4_moe:** tool parser and stop lib.rs:9264 and 9315; thought splitter lib.rs:9270.
- **Effort-ladder templates** (step35, hy3, Qwen3.8, dsv4, glm5): lib.rs:9023.
- **Forced tool grammars** (tool_constraint.rs:22): refuse dsv4, hy3 and glm5; Gemma dialect for gemma4; Qwen dialect for the rest.

Vision placeholder arms are door-keyed:
- step35: MEMRA_STEP_VISION_DIR, lib.rs:4801.
- glm5_next: default on when the tower loads, lib.rs:4913.
- gemma4: MEMRA_GEMMA_VISION, lib.rs:4956.
- qwen-VL (qwen35 / qwen35_moe): MEMRA_VISION_DIR, lib.rs:4991.

Pixel decode runs after admission in `decode_pending_vision` (lib.rs:9382).

`SpecGrammar` (constrained.rs:912) is the grammar hook inside MTP verify. The engine reaches it through a trait object, so the static graph has no edge for it. Its reach is the `mtp_spec_capable` families (qwen35, qwen35_moe, step35, hy3). `PostThinkGate` (constrained.rs:631) serves think-forced templates (step37 named).

`host_glm.rs` is GLM/MLA-only (glm5_next, glm_dsa) except `read_f32` (host_glm.rs:13), which every family's host demote uses (worker.rs:9621). The whole host tier sits behind `MEMRA_KV_HOST_MB` (default 0).

### Device-specific parts
Almost nothing in this slice is device-keyed; it runs on the CPU and reaches every device through the requests it shapes. The exceptions:
- kv_vmm grow placement delegates to the engine's card-class helper (kv_vmm.rs:56). The door is MEMRA_KV_ALLOCATOR, default OFF.
- health.rs:1234 probes `nvidia-smi` on every GPU.

### Effect kinds
- **numeric:** sampling, think/effort, prompt rendering, vision placeholders, stops, parsers, grammar masks, capture output.
- **policy:** deadline gates (lib.rs:2661), admission and budget, n-choice caps, route contracts, auth.
- **memory:** vision patch reservation (lib.rs:8846), admit_memory, kv_vmm, host_glm.
- **speed:** affinity, darklane, handoff_io, prime_fairness.
- **observability:** the metrics and telemetry modules (listed in exact_items).

### Where the impact set is wide, and why
`lib.rs` and the three translation surfaces are `*` for families and routes by construction. Every chat request crosses `build_chat_request_with_trace`, and the dialect arms sit inside that one 429-line function. Splitting the dialects into a caps-derived `ChatDialect` would make those arms family-local.

The vision walker choice is process-global (lib.rs:4899). A step, gemma or glm5 vision door therefore changes text or image rendering for every other model in the same process. Keying it per model removes those cells.

### Top findings
1. **High.** On a metered deployment, the budget path fills `prepared_prompt` on the HTTP side (lib.rs:9981). The worker then skips its post-render steps, including the embedding EOS pooling append (worker.rs:33478), so `/v1/embeddings` is pooled one position early. The worker's own comment measures that at about 0.3 cosine against the reference.
2. **Medium.** The same path skips `vision_special_id_guard` (worker.rs:33487). A related drift: `render_prompt_ids` is a third copy of the render and does not publish `prompt_text`, which kills the text-extension reuse tier for chat on metered deployments.
3. **Medium.** A malformed `MEMRA_MODELS` silently falls back to the hard-coded qwen35 pair (lib.rs:6647).
4. **Medium.** The decoupling cuts above: per-model vision walkers and per-dialect chat arms.
5. **Low.** Four doors are past their decide-by date: MEMRA_KV_ALLOCATOR, MEMRA_ADMIT_BY_MEMORY, MEMRA_KV_HOST_HANDOFF_IO and MEMRA_BACKGROUND_RESPONSES.
6. **Low.** StopScrubber and SurfaceScrubber are near-copies that can be merged.
7. **Low.** `kv_hat` survives only as a test oracle.
