## S12: memory tiers (MoE expert residency, spill, CPU experts, pinned host, memra-tier)

### What the slice does
This slice holds memra's memory-placement layer. None of it defines a numeric program of its own. Every component either moves bytes that a kernel elsewhere consumes or accounts for memory. The impact question is therefore which arms run by default, and whether a bug could hand a kernel the wrong bytes.

- **`moe_cache.rs`** is the GPU SLRU expert slot cache. It has been default ON since 2026-07-08 (`moe_cache.rs:29`). It is built lazily on the first MoE forward whose experts stay host-resident (`lib.rs:6613`), with the host/VRAM choice made by `ResidentPlan::should_reside` (`hybrid.rs:325`). It is the hot path of the `spill` regime for every HybridModel MoE family: qwen3_moe, qwen35_moe, olmoe, minimax_m3, hy3, gemma4_moe, glm_dsa, glm5_next, step35 and mimo_v2. Dsv4Gpu (deepseek_v4) and Qwen4ExpGpu (qwen4_exp) never call `with_moe_cache`.
  - **Sizing.** The cache auto-sizes to 0.85 of free VRAM, capped by a 0.80 hard fraction (`moe_cache.rs:815-821`).
  - **Dispatch.** The default arm is first-miss admit (`2260-2312`).
  - **Device-table arm.** The zero-DtoH arm (`prewarm_layer`/`layer_dev_row`, `2605-2701`) is reached only by families passing `dev_ok` (`hybrid_forward.rs:13773-13777`): qwen3_moe, qwen35_moe, olmoe and gemma4_moe. It is never reached by sigmoid-router families or hy3.
- **`spill.rs` / `spill_pread.rs`** are the disk tier and positioned-read backends.
  - **Disk tier.** Behind `MEMRA_SPILL_DISK`, for GGUF MoE models only (`hybrid.rs:4590-4595`).
  - **Positioned reads.** Behind `MEMRA_SPILL_IO` (default `mmap`; `spill_pread.rs:77`).
  - **Default reach.** Only the fail-closed mode parse runs by default.
  - **mmap fallback.** Mmap-backed experts (for example the safetensors store) still reach `dispatch_disk`'s fallback arm (`moe_cache.rs:1942-1947`).
- **`cpu_experts.rs`** is a dlopen'd CPU companion for Hy3 only (`hybrid_forward.rs:13662`). It sits behind `MEMRA_CPU_EXPERT_LIB` and is a different numeric configuration from CUDA.
- **`banked_residency*`** is the `--experts-via-tier` qualification installer, pinned by SHA256 to one Qwen3.6-35B-A3B IQ4_XS GGUF (`native.rs:33,677`). The exception is `SLOT_TAIL_PAD_BYTES` (`banked_residency.rs:414`), which sizes every default slot.
- **`tier_transfer.rs`** is the CUDA transfer engine of the host KV tier: D2H demote, H2D promote, D2D capture/restore, and GPU receipts loaded from a fatbin by kernel name. It is constructed only when `MEMRA_KV_HOST_CONTRACTS=1` and `MEMRA_KV_HOST_MB>0` (`worker.rs:4935, 27125`), for GGUF text models only.
- **`pinned_host.rs`**
  - `PinnedHostBuf` is a shared utility, default-reached through dsv4 verify-workspace host scalars (`dsv4_gpu.rs:15856`) and the glm5 TP H2D arena.
  - `PinnedHostArena` is used only with `MEMRA_GLM5_TP_KV_HOST=1`.
- **`model_memory*.rs`** handles admission accounting for PP stages, step TP/EP ranks and glm5 TP peers. Its effects are policy and memory only.
- **`memra-tier`** holds frozen CPU contracts and conformance schedules. Its production reach is limited to:
  - the host-tier door (contracts, governor, `receipt_digest`);
  - the experts-via-tier gate;
  - the qwen4_exp PLE-rows gate.

  The io, object_store, peer, placement and telemetry modules, and most conformance functions, are test-only.

### Effect kinds
- **Residency and spill.** These are built to be bit-identical: a hit and a miss feed the same bytes (`moe_cache.rs:11-13`). A correct change is therefore speed or memory only. I still label dispatch, slot and pointer-table code `numeric`, because a wrong slot means wrong weights.
- **CPU experts.** Truly numeric.
- **tier_transfer.** Numeric for restored or promoted KV, but default-off.
- **model_memory.** Policy and memory only.

### Device-specific parts
- `PinnedKind::for_device` uses Cached pinned memory on RTX PRO 6000 Blackwell and write-combined on everything else (`tier_transfer.rs:70-71`).
- `kv_vmm_placement_for_device` is inline on a full-power PRO Workstation and helper elsewhere (`102-119`, MEMRA_KV_ALLOCATOR=vmm).
- The span receipt grid scales with SM count (`946-953`).

All three are behind default-off doors.

### Where the impact set is wide, and why
- **moe_cache.rs** reaches ten families on every GPU in the spill regime. The width comes from mixing default SLRU code with gate-only banked code (`1273-1835`) and with several default-off doors (cold bypass, prefetch, LFU, size-aware, pread). Moving the banked arms into the existing `moe_cache/banked_native.rs` would narrow edits there to one gate cell.
- **pinned_host.rs** is a shared utility. Its default reach includes deepseek_v4 dsv4_serve.
- **tier_transfer.rs** looks wide (`*` families) but is reached only behind its door. Over 40% of the file is tests (`4298-7917`).

### Top findings
1. **Four doors in this slice are past their decide-by dates without a decision:**
   - `MEMRA_KV_HOST_CONTRACTS`, 2026-10-05 (`FLAGS.md:1462`). It gates all of tier_transfer, with N=1 executed-not-qualified receipts.
   - `MEMRA_MOE_COLD_BYPASS`, 2026-10-10 (`FLAGS.md:450`).
   - `MEMRA_MOE_PREFETCH`, 2026-10-04 (`FLAGS.md:861`). The PRO card's receipt says it qualifies as that card's naked default, but no flip happened.
   - `MEMRA_KV_ALLOCATOR`, 2026-10-04 (`FLAGS.md:318`).
2. **`MEMRA_MOE_SLOTS` and `MEMRA_MOE_VRAM_FRAC` fail open** (`moe_cache.rs:805,818,821`):
   - typos are ignored;
   - a forced slot count is silently clamped to the hard ceiling, although FLAGS promises an exact count;
   - a negative fraction gives an 8-slot thrashing cache with no warning.
3. **Stale docs:**
   - lib.rs `with_moe_cache`/`moe_cache_enabled` still describe a default-off cache (`lib.rs:6602,6691`);
   - the `new()` doc claims a 256-slot floor (`moe_cache.rs:777`);
   - Hy3 CPU-expert comments still say llama.cpp (`hybrid_forward.rs:13657`);
   - the `pinned_host` module doc says portable and startup-only (`pinned_host.rs:1`).
4. **Dead code.** `spill::SpillBlock` and `spill::Tiered` are unused. Most memra-tier conformance schedules are test-only by design; `bundle_integrity` has no reference anywhere.
5. **Mergeable.** `submit_d2d_capture` and `submit_d2d_restore` duplicate their whole batch skeleton (`tier_transfer.rs:2386` vs `2590`).
