# dsv4_gpu.rs: the DeepSeek-V4 GPU engine (slice S06)

## What it is
`crates/memra-engine/src/dsv4_gpu.rs` (26,444 lines, about 24,700 of them non-test) is the whole DeepSeek-V4-Flash engine. It never goes through `HybridModel`. `dsv4_serve::load` builds it through `Dsv4Gpu::load_placed` (3548) when `is_dsv4_dir` matches. The gate bins build it through `Dsv4Gpu::load` (3527). Every outside caller in facts.tsv is `dsv4_serve.rs` or a `dsv4_*` gate. So almost the whole file is **deepseek_v4-only**. The one exception is the sampler pieces: `Dsv4SampleCfg`, `dsv4_pos_uniform` (24409-24429), `Dsv4PenaltyCfg` (24642) and the phase bracket (2030-2136). `dsv4_sampler.rs` and `glm5_tp_sampler.rs` reuse them, so they also reach **glm5_next x tp** (behind MEMRA_GLM5_TP_DEVICE_SAMPLE, default off).

## The served program and its doors
`load_placed` resolves about 20 doors once (3556-3941). The naked default is:
- **Placement:** TP/EP with attention TP2, from `dsv4_serve` resolve_topology. EP pair is implied (3635), and the topology plan is built at 3645.
- **Expert program:** matrix. It is not a door: `matrix_expert_program_resolved` (3575). `validate_matrix_program` (2937) then requires the RefFp8Round variant and native NVFP4 experts.
- **Decode path:** `device` (3788).
- **Dots:** f32x (3821).
- **Dense linears:** fp8 (3911).
- **Verify top-k:** device.
- **Indexer scorer:** knee (808-843, speed only).
- **Plain sampler:** device on TP/EP, host on PP (3929).
- **PDL chain:** on (3559, process-global).
- **Vocab-parallel head:** on (20652).
- **HC24 split dots:** 16 slices. The CUDA host code reads MEMRA_DSV4_HC_DOT_SPLIT through `memra_dsv4_hc_dot_split_slices_for_gate` (10127, 16607).
- **DSpark drafter (`dflash`):** behind MEMRA_DSV4_DRAFTER=dspark (4272), so a naked launch reaches no dflash cell.
- **Spill and parked prefixes:** C4 host history (MEMRA_DSV4_C4_HOST_MB) and parked prefixes (MEMRA_DSV4_KV_HOST_MB) are both off by default.

## Hot paths per route
- **plain (default TP/EP):** `decode_step_fast_tap` (12499) goes to `decode_step_tp_ep` (11544), which calls `tp_ep_trunk_walk` -> `attention_rows_dev` (17809) and `post_attention_moe_verify_dev` -> `moe_verify_dev` (19896), whose EP arm is at 20056. Full-token replay graphs wrap this program. Admission (`validate_full_token_program`, 9302) is pinned to the 43-layer, 4096-wide 0731 shape, with greedy or vendor-default sampling only. Cadence variants are at 11668.
- **batch:** `decode_rows_run` (21744) dispatches to the TP/EP B-row walk or its graph (22052-22938; `DSV4_ROWS_GRAPH` defaults on at 14774). The multi-row replay attention is at 18305.
- **prime / chunked_prefill:** `prefill_with_cache_chunked_yielding` (6863). Under matrix the first token goes through `decode_step`, and the rest goes through `verify_batch_dev_output` (20718) -> `verify_batch_tp_ep` (21051).
- **dflash:** `dspark_*` and the spec drivers (12958-14443, 23316-23990). Drafter MoE goes through `dspark_moe_tp_ep` (6531) on TP/EP and the prefill-class `moe_forward` (5994) on PP.
- **pp (MEMRA_DSV4_TOPOLOGY=pp):**
  - plain step: `decode_matrix_step` (11479).
  - pipelined steps: 12696-12818.
  - PP verify walk: 20833-21044.
  - grouped no-EP MoE arm: 20316.
  - layer split: `dsv4_split_for_tail_reserve` (1688).
- **prefix_cache:** `snapshot_decode_state` and `restore_decode_state` (7973-8329).

## Gate-only code inside the serving file
About 5k lines run only after `arm_reference_expert_program_for_gate` or under the legacy decode path, which the matrix default refuses:
- `forward_impl` refuses at 6973, and `block_forward` sits behind it.
- the compressor helpers (5063-5250).
- legacy `block_decode` and `cmp_decode` (8483-9191).
- the non-matrix device step (10032-11474).
- NextN MTP (4245, 7231).

The many `*_for_gate` setters, counters and probes (2324-2648, 9512-9838, 14875-15510, 23993-24255) are also gate-only, with one trap: some `_for_gate` names run on the serving path (4382, 4384, 10127).

## Device-specific parts
The file has no cfg!, arch or SM-count predicate, so every region keeps devices `*`. What changes per device lives in the kernels it calls, through the build-variant liveness in other slices, and in the indexer knee constants. Those constants were measured on a PRO 6000 but apply to every card, which matters only for speed.

## Effects and where the impact set is wide
- **Numeric:** dispatch on attention, MoE, head, compressor and commit (17809-23301) carries numeric effect for every default route at once (plain, batch, graph, prime, dflash, tp, ep).
- **Memory and policy:** load and allocation code (3548-4430, 7356-7810, 15567-16097).
- **Speed, observability or none:** profiling (2030-2136), PDL (3559) and the counters.

Three things widen the set beyond deepseek_v4:
1. the shared sampler types used by glm5_tp_sampler;
2. the process-global PDL flag, which tp_ar.cu (glm5 TP) also reads;
3. the reverse dependency on generic `lib.rs` MoE f16g doors in `validate_matrix_program` (2949), `full_token_moe_program_admitted` (1504) and `rows_steps_supported` (2674). A lib.rs door default change can stop dsv4 from booting or turn off replay with no dsv4 file in the diff.

## Top findings
- **Gate coverage (medium):** `Dsv4Gpu::load` defaults to PP-2 (3541), but serving defaults to TP/EP. 33 of 46 dsv4 gate bins never arm TP/EP, so they do not qualify the served program.
- **Stale door with dead arm (medium):** `set_matrix_ep_graph_for_gate` is past its decide-by date (2026-09-21) and has no caller, so the matrix-EP graph arm in `moe_verify_dev` (20151-20234) is dead.
- **Silent door (low):** MEMRA_DSV4_DRAFTER takes any value without refusing (4272).
- **Preview artifacts (low):** ClampOnly Preview checkpoints cannot load under the matrix program (2946).
- **Cleanup (low):** a stale module header (18-22), 10 dead accessors, and the merge of `dots_m_dev` with `dspark_head_dots`.
