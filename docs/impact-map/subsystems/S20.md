## S20: memra-gguf (config, plan, packs, manifests, sources) and memra-cli

**What it does.** This slice runs at load time and decides what program a model gets. `ModelConfig::from_gguf` (config.rs:1385) and `ModelConfig::from_hf` (config.rs:1773) turn artifact metadata into one config. `model_packs::compile_for_load` (model_packs/mod.rs:221) picks the first `PACKS` entry whose `matches_config` holds (mod.rs:216) and compiles the canonical `ModelPlan` (model_plan.rs:990). `checkpoint_binding::bind_source` (checkpoint_binding.rs:199) binds the pack's tensor contract before any upload. `TensorSource` implementations then supply the bytes. `execution_manifest` and `op_registry` turn plan operations into route admission.

Almost nothing here runs per token. But every byte and every route choice downstream flows from it, so the file defaults are wide on purpose. Devices are `*` throughout: the code runs on the CPU but fixes what every GPU build computes.

**Hot paths per family and route**

- **Pack selection.** The order of `PACKS` (mod.rs:176) is load-bearing.
  - qwen3 and qwen35 refuse configs with experts. qwen3_moe and qwen35_moe accept the dense arch name when experts are present.
  - The gemma packs exclude E4B (gemma4_dense/mod.rs:45).
  - deepseek_v4 splits on `nextn==3` into a DSPARK drafter plan (deepseek_v4/mod.rs:103).
  - llama_dense is last and refuses windowed, scaled-rope or non-silu configs.
  - Two packs inject vendor sampling defaults: step35 (0.5/0.9, step35/mod.rs:38) and hy3 (0.9/1.0, hy3/mod.rs:79). These are numeric for requests that omit sampling parameters.
- **Plan arms.** `compile_attention` has one arm per family:
  - glm5 KDA/MLA (model_plan.rs:2018)
  - glm_dsa MLA, GGUF only (2074)
  - dsv4 compressed MLA (2118)
  - GDN for qwen35/qwen35_moe/qwen4_exp (2176)
  - generic full/SWA (2220)

  `attention_geometry` adds gemma (2264) and step35 (2316). The MLP, router, activation, residual and norm-transform functions (2417-2648) each branch on the per-family sub-configs. Every arm is labeled with its family set.
- **Manifests.** `decode_batch_program` picks the decode program:
  - Gemma for gemma4_dense/gemma4_moe (execution_manifest.rs:551)
  - SlidingGatedMoe for step35 only (555)
  - Generic for everything else

  `decode_batch_unconverted` (glm5_next, deepseek_v4) and `gdn_dspark_compatible` (qwen35, qwen35_moe, qwen4_exp) key the eager-only class and the dflash attach. The row table in op_registry.rs:196-438 is the single source for:
  - carried prime
  - batch
  - graph
  - MTP spec and GLM5 spec
  - PP
  - chunked prime

  A row flip changes admission for every family whose trunk carries that operation. For example, the SigmoidRouter row reaches glm5_next, mimo_v2, minimax_m3, hy3, glm_dsa and step35.
- **Safetensors bytes.** `SafetensorsSource::find` (source.rs:2840) decides the numeric program of every safetensors-served model:
  - NVFP4 modelopt weights are repacked to GGUF NVFP4 (2928).
  - Large 2-D BF16 weights are re-encoded to Q8_0, and the head to Q5_K (2957-2993). `MEMRA_FULL_PREC=1` bypasses both.
  - FP8 E4M3 is re-encoded to Q8_0 (2994).
  - Transform targets (qwen35 V-reorders, step35/m3 norm +1, glm5 MLA kv split) take a separate arm (3032).

  `hf_mapping::resolve_ggml` (hf_mapping.rs:754) holds the per-family name maps and folds.
- **GGUF.** `GgufFile::open` (lib.rs:939) and `dequant::dequantize` (dequant.rs:49) serve every GGUF artifact; the dequant arms split by format. The calibrated A4 prefill program (`PrefillFp4::from_gguf`, qwen35/activation.rs:74) only reaches qwen35 27B NVFP4 GGUFs, and only the prime route.

**Device-specific parts.** None in memra-gguf: no cfg or arch checks (the dequant.rs arch candidate is a false positive). `placement.rs` reaches only the multi-card routes, which the device table limits to rtx5090 and rtxpro6000.

**Env doors.**

| Door | Default | Effect |
|---|---|---|
| `MEMRA_MOE_MMAP_ADVICE` | random | spill speed |
| `MEMRA_MOE_SLAB_POPULATE` | fits | spill speed |
| `MEMRA_REPACK_EXTERNAL_ROOTS` | unset | admission policy |
| `MEMRA_FULL_PREC` | off | numeric when set |
| `MEMRA_FP8_FOLD` | off | numeric, lossy research arm |
| `MEMRA_A4_DISABLE` | off | gate harness only |
| `MEMRA_REWRITE_BUNDLE` | off | receipt admission |

**Effect kinds.**

- config, plan, sources, hf_mapping, dequant, nvfp4_repack: numeric.
- manifests and op_registry: policy.
- tensor_contract and checkpoint_binding: policy, except that output-head ownership (checkpoint_binding.rs:139) picks embedding-as-head.
- Expert mmap and slab code: speed and memory.
- memra-cli, micro_gguf, d2t, spec_oracle and the speech/TTS packs (whisper, nemotron_rnnt, qwen3_tts) reach no serving cell. They are policy/observability for qualification, or none.

**Where the impact set is wide, and why.**

- `from_hf` is one 825-line function holding every family's normalization.
- `SafetensorsSource::find` mixes the hy3, MiMo and qwen35_moe quirks into the generic re-encode path.
- `plan_sha256` hashes the full plan Debug output (execution_manifest.rs:475), so any plan-type change invalidates rewrite bundles for every family.

Each of these is filed as a decoupling finding with its cut.

**Top findings.**

1. A qwen3next-named MoE GGUF compiles an ungated shared expert (model_plan.rs:2470). The contract then refuses its `ffn_gate_inp_shexp`, or the reference and tuned programs diverge.
2. The `MEMRA_FP8_FOLD` door is three months old with no decide-by and no receipt (source.rs:2312).
3. The head Q5_K re-encode checks the total element count, not `in_f % 256` (source.rs:2977). Latent row-straddle bug.
4. `select_activation` is the tested policy, but model.rs re-implements the lookup twice.
5. Stale docs: DeepSeekV4 is called "loader lane only" (config.rs:29), and the PIPELINE note names step35 as a GDN family (execution_manifest.rs:624).
6. Dead code: `n_layer_total` is unread and disagrees between GGUF and HF. Of the 68 dead candidates, 46 are confirmed prod-dead (mostly test-only callers), 4 are unsure, and 18 are rejected (fn-pointer pack fields and cfg(test) helpers).
