## S18: memra-server worker.rs, second half (22674-42208)

This slice is the serving engine room. Every HybridModel family is served from one worker thread (`run`, worker.rs:26013). Each request is routed by `admit` (34356) and advanced by `prefill_tick` (38466), `step_session` (39666), the batched host half `advance_sample_emit` (38960) and three drafter steps (`step_gemma_spec` 40431, `step_dspark_spec` 40610, `step_glm5_spec` 40946). The prefix snapshot/restore/digest code (22674-24500) and the decode chunk policy (39280-39537) also live here. Lines 42210 to the end are `#[cfg(test)]` modules.

### Boot (run 26013-27375)
- DeepSeek-V4 directories leave the hybrid path at 26132 (`dsv4_serve::load/spawn`). `handle_cmd` (33085) forwards them over a channel, so deepseek_v4 reaches this file only through boot, routing and caps.
- Other directories load through `Box<dyn TensorSource>`: a Hy3 repack when `manifest.json` exists, else safetensors (26177). Files load as GGUF (26245). `+draft` attaches an external MTP head (26274), and `MEMRA_REWRITE_BUNDLE` (26334) flips every `rewrite_allowed` gate engine-wide.
- Class sets are built once: `eager_only` (Gemma program, E4B, HyperConnections) and `eager_decode` (26600-26649). By default `eager_decode` holds only glm5_next, because gemma4 batched decode is default-on and hyper batch is default-off.
- Drafter attaches are door-gated and default-off: gemma (26657), DFlash on `gdn_dspark_compatible` plans, i.e. qwen35, qwen35_moe and qwen4_exp (26744), and the glm5 TP verdict (26718).
- Vision towers: qwen-VL, gemma and step37 are off by default. glm5 defaults ON when the directory carries `model.visual.*` (26916).
- Boot calibration (41529) runs one probe generation per spec-capable model. It is memory and policy only.

### Tick (run 28022-32987)
1. Admission: constrained pre-compile, lane caps, the optional first-token gate, the cost model, then `admit`.
2. With `MEMRA_SERVE_BATCH=0`: a serial loop over `step_session` (30161).
3. Default phases, in order:
   - Spec demotion at HIGH (30347): MTP, dspark and glm5 sessions hand their cache to batched decode. This is a numeric program switch that depends on load, and is claimed exact for greedy only.
   - Spec bursts, cold first (30661).
   - Prefix dedup fan-out (30934), interactive concat prime batching (31004), per-session `prefill_tick` (31234).
   - The eager-only per-session decode loop (31383).
   - Batched chunks, serial or PP-2 dual wave (31495).
   - Dark-lane batched and single primes inside the SLO headroom (31728, 31862).

### Per-family hot paths
- **qwen35 / qwen35_moe** (MTP): `spec_eligible` (35004) -> step_session spec arm (39719). The GDN+MoE plans (qwen35_moe, qwen4_exp) force replay, so constrained spec is refused for them (33843).
- **DFlash** (qwen35 class): `dspark_prefers_cold` (35101) -> step_dspark_spec.
- **gemma4**: batched decode with cap 8 (39436). Prime is chunked (`monolithic_prime_model` excludes gemma when its chunked-prime receipts exist). Spec runs only behind MEMRA_DRAFT.
- **glm5_next**: eager per-session decode and the hyper plain prime walker (38638). Spec needs MEMRA_GLM5_SPEC; the TP device-logits arm sits at 40287.
- **step35**: SlidingGatedMoe cap 8 (39421), the dead-kill-switch refusal (26374), its own concat prime via `concat_prime_pp_eligible`, and SWA-ring prefix exclusion.
- **Generic dense/MoE**: the exact16 vs 8 tier (39452).

### Device-specific parts
- `serve_devpenalty_from` (39128) is the only build-arch key in the slice: device penalty sampling is ON for qwen35 on 120a builds (rtx5090, rtxpro6000, gb10).
- StepTowerPlacement chooses a TP rank device (24557). `vision_placement_admissible` checks PP intake engines (24634).
- `decode_chunk_policy` arms PP dual or wavefront from PP doors (39459). `is_multi_device_deployment` gates n-choice and predictive enforcement (25841).

### Where the impact set is wide, and why
`run` (fan-out 632) and `admit` (243) put every family's boot, routing and tick in one item each. Any edit there maps to * x *, even an edit to a block that only gemma or dspark can reach. The decoupling finding names that cut. Several shared arms also carry numeric effect for every family: `advance_sample_emit`/`devsample_meta`, `prefill_tick`'s prime-vs-tokenwise choice, the chunk caps, and spec demotion.

### Top findings
1. **High.** The dark-lane concat prime (31737-31791) admits carried continuations of routed-MoE plans without the CARRIED_PRIME guard the interactive path enforces (31054). The engine checks only the rewrite, so the program a request primes under depends on its lane and its peers.
2. **Medium.** Under MEMRA_SERVE_BATCH=0, gemma, dspark and glm5 sessions (admitted without a batching check) reach plain step_session with no cache and fail as worker faults (30192).
3. **Medium.** Batched decode bytes depend on batch composition (30273), which contradicts the isolation claim at 39374.
4. **Medium.** The W1 sub-floor boundary still sends prompt tokens to decode_step (38581).
5. Smaller items: the dead `evaluate_decoupled_admission` (25973); the devpenalty and glm5 K defaults extended past their single-rig receipts; the duplicated prime formers and step_session/prefill_tick twins; spec-membership predicate drift; and stale docs.
