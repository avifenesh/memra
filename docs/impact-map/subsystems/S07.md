## S07: DeepSeek-V4 serving route, engine helpers and CPU oracle

### What the slice is
DeepSeek-V4 never runs through `HybridModel`. `worker::run` checks `is_dsv4_dir` (crates/memra-server/src/dsv4_serve.rs:55). A matching directory gets `dsv4_serve::load`, which calls `Dsv4Gpu::load_placed` and builds a dedicated set of serving lanes (`spawn`, L1257). This slice holds that server route, its memory door (`dsv4_admit.rs`) and the engine helpers `Dsv4Gpu` composes:
- topology (`dsv4_topology.rs`)
- the two-card joins and expert parallel (`dsv4_ep.rs`)
- the matrix expert program (`dsv4_grouped.rs`)
- replay graphs (`dsv4_graph.rs`)
- C4 residency and position-split gathers (`dsv4_c4.rs`)
- attention TP2 packing (`dsv4_attention_split.rs`, `dsv4_attention_tp.rs`)
- the device sampler (`dsv4_sampler.rs`)
- the door registry (`dsv4_doors.rs`)
- the FFI declarations (`dsv4_ffi.rs`)

It also holds the memra-gguf CPU oracle (`dsv4_forward.rs`, `dsv4_decode.rs`, `dsv4_dspark.rs`).

### Hot paths on a naked launch
- **Placement:** TP/EP with exact attention TP2 (serve L262). PP-2 is reached only with `MEMRA_DSV4_TOPOLOGY=pp` (L263).
- **Lanes:** 16 lanes, and `MEMRA_DSV4_ROWS` equals the lane count (L230, L966). Plain decode steps are coalesced into B-row steps (`Coalescer::step` L1781, `rows_step` L2001).
- **Prefill:** chunked at 512 (L456). The matrix program refuses chunk 0 (L916), so the monolithic prime, the tokenwise restore and the cold spec drivers (L2994-3024, L3076-3081, L2498-2508) are unreachable from a server.
- **Greedy plain requests:** they arm full-token replay (L3106, `ReplayPair` dsv4_graph.rs:141) and replay whenever they step alone (L2017). Multi-row batches take the captured B-row graph (`RowsReplay` L522) through `decode_rows_draw` (L2061).
- **Sampled plain requests:** they use the device sampler (L3155). Replay applies only at temperature 1, top_p 1, top_k 0 with no penalty (L3179).
- **MoE:** every layer runs `execute_matrix_local` (dsv4_ep.rs:1450) into `GroupedWork`. Rows==1 uses the stream visitor, 2..MROW rows use the mrow visitor, prefill chunks use split-K (dsv4_grouped.rs:581-608, 695-727).
- **Joins:** attention and expert joins use `all_reduce_into` on the push arm (L495). Attention halves are joined by `gather_rows_into` (L673).
- **Default-OFF doors:** DSpark spec (`MEMRA_DSV4_DRAFTER=dspark`, serve L2922), the parked-prefix tier (`MEMRA_DSV4_KV_HOST_MB`, L478-785) and host C4 (`MEMRA_DSV4_C4_HOST_MB`, dsv4_c4.rs:100). `response_format` is refused (L2818) and min_p is refused (L2858).

### Device and format
No branch in the slice keys on arch or card class. The only device-shaped input is the world=2 requirement (dsv4_topology.rs:64), so the device sets stay `*`. The sole qualified card is the RTX PRO 6000 pair; the doors registry `measured_on` strings are provenance only. Format arms live in the loader: NVFP4 at dsv4_forward.rs:543, MXFP4 and FP8 block-128 at L564-582, BF16/F32 at L595. The act-quant contract is keyed on the encoding revision (serve L860-861).

### Effect kinds
- **Numeric:** the drivers, joins, matrix program, sampler, loader and the stop/emit logic, which decides which tokens are committed (L2317).
- **Speed:** push/pull joins (two-rank sums are commutative), lanes, the turn lock.
- **Memory and policy:** admission (`dsv4_admit.rs`), calibration (L1095).
- **Observability:** the lane watchdog, the receipts, EP route stats.
- **Gate-only:** `dsv4_ep_graph.rs`, `dsv4_small_kernel_gate.rs` (mask starts at all ones, dsv4_gpu.rs:3981), `dsv4_full_token_replay_gate.rs` and `dsv4_default_engagement_gate.rs` (bin `#[path]` includes), and `dsv4_source_tape.rs`. These change gate verdicts only.

### Where the impact set is wide, and why
1. `dsv4_ffi.rs` is not dsv4-only. hyper.rs:50 (glm5_next hyper trunk), mla_ffi.rs:1452, qwen4exp_gpu.rs:9499 and mimo_source_moe.rs:17 call its declarations, and `ck()` is shared.
2. `dsv4_sampler.rs` is used by glm5_tp_sampler.rs:11, so the glm5_next tp route is in its blast radius.
3. `dsv4_forward.rs` mixes the CPU oracle with production pieces `Dsv4Gpu` imports (dsv4_gpu.rs:31): the loader, rope tables, index builders, host Sinkhorn and the expert-arm seam. Most of the file is cpu/reference-only (L736-2188), but a file-level rule cannot see that. `dsv4_decode.rs`, and `dsv4_dspark.rs` apart from `DsparkConfig::load`, reach no serving route.
4. `dsv4_grouped.rs` depends on generic lib.rs MoE doors (`moe_f16g_*`, dsv4_grouped.rs:818). Changes to those doors' defaults land on dsv4.

### One numeric program per request
Requests are claimed bit-equal across one-row eager, replay and B-row widths (`dsv4_rows_gate`, serve L1994-2000), and across mrow, stream and split-K visitors. These are gate claims, not constructions. Any edit to `Coalescer::step`, `rows_step` or the visitor selection should run the rows and replay identity gates.

### Top findings
- Decoupling cuts: `dsv4_forward.rs`, `dsv4_ffi.rs`, `dsv4_sampler.rs`.
- Server arms unreachable on serving (cold spec drivers, monolithic prefill), and a dead arm in `rows_step` (L2074).
- Dead column-partition and wo_b partial-sum code in `dsv4_attention_split.rs`.
- Four copies of the projection launcher in `dsv4_grouped.rs`.
- Flags past their decide-by dates: `MEMRA_DSV4_TOPOLOGY` (2026-10-09), `_SAMPLER` (2026-10-08), `_SESSIONS` and `_ROWS` (2026-10-11).
- Stale "gate-only" or "PP" docs in dsv4_graph.rs:1, attention_tp.rs:1, topology.rs:3, sampler.rs:1, serve.rs:2 and the door registry. `SERVED_PROGRAM` assumes a resident drafter that the naked launch does not load.
- `is_dsv4_dir` routes on a substring match.
- `DsparkConfig::load` panics instead of returning an error.
- The replay census hardcodes the 43-layer geometry (dsv4_graph.rs:279).
