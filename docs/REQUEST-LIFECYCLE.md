# Request lifecycle diagnostics

`MEMRA_TTFT_TRACE=1` preserves the existing TTFT line and emits bounded `[request-lifecycle]` JSON for the OpenAI completion and chat-completion routes. It is a diagnostic opt-in; normal requests allocate no trace state when disabled.

An optional `x-memra-trace-id` header carries exactly 32 lowercase hexadecimal characters. This key joins a client attempt to the server-generated request ID even when cancellation occurs before admission has produced response headers. It provides no authentication or request authority. Invalid values are not echoed into the log and make the diagnostic history invalid without changing request handling.

Each record includes the process ID, trace ID, ordered sequence number, elapsed nanoseconds from that trace's start, request/model identity, worker-run generation and dispatch route. Capture tooling must additionally bind the process boot/start identity and the actual source and binary. The worker generation is process-local.

The HTTP wrapper distinguishes a dropped pending response, a dropped SSE body, and normal body EOF. Queue overflow and receiver drop are separate worker observations; neither alone proves a client cancellation. The instrumented main-worker queue and active-abort paths record retirement only after the request's owned state and admission/prefix-pin resources are released. Production retirement records use the `Aborted` outcome and an explicit `WorkerQueue` or `ActiveSession` site. Unscoped retirement is a test-only helper; normal completion and failure are not instrumented retirement outcomes. Panic and OOM replay do not produce a clean retirement record. Non-SSE response transport is unchanged.

Asynchronous restore parking records the actual `requeued` event. Its trace cannot qualify as a clean single-attempt cancellation, including when a later lost observation quarantines retained resources. Dropping a closed queued request while a matching pending or ready restore exists does not emit `WorkerQueue` retirement: the restore still owns its cache, pin or ticket. The existing restore owner continues its normal polling, expiry and quarantine behavior. A restore owned by another request does not block this request's retirement evidence. This does not add a GPU wait or free pending resources early.

Actual prime observations are separate from legacy `mark_prime_start`/`mark_prime_end`, which remain elapsed timing only, including cached empty-suffix MTP calls. A nonzero actual operation opens a quantum using the trace's clock. Its input rows come from the selected frozen range, direct input slice or one prompt token; they are not a queue-length estimate or a count of total device work.

The saved MTP, DFlash, GLM speculative and GLM plain adapters expose read-only next-chunk metadata. Their observation wrapper preserves every existing advance, return, yield and error boundary. The last advance and mandatory same-turn finalization already form one worker quantum: its event remains open through finalization, including DFlash's bounded carry flush. Exactly one end is recorded on ordinary advance/finalization return. Failure closes with `completed=false` and unknown remaining work. Successful `Some(0)` is emitted only after no whole-request prime work remains. A GLM plain segment with later queued input reports unknown remaining; an actual later segment or one-token tail must finish before the prompt can be marked complete. Quantum end is a host-operation return, not a GPU-quiescence or resource-release proof.

Direct text prefill in `prefill_tick` records its selected prime call or prompt-token operation without changing the input partition or model call. Empty/cache-only wrappers do not open a quantum. OFF MTP/DFlash synchronous paths that do not use a saved walker, legacy scheduling, and vision/capture setup remain unobserved by this seam; missing quantum records do not prove a cache hit or no prime work. `phase` is the last observed lifecycle state, not continuous coverage through uninstrumented code. A stale `queued` value cannot qualify queued cancellation without an explicit worker-queue retirement-site observation.

Consumers must reject incomplete bindings, invalid ordering, event suppression, and missing final records. A failed quantum immediately invalidates the history; later abort or retirement cannot make it clean or manufacture prime completion. Each record advertises `ordinary_event_limit: 8192`. The producer permits at most that many ordinary records, one overflow record and one final record per trace. The controller must derive the expected quantum/event budget from the frozen operations before execution and refuse a budget that exceeds the limit. This fixed diagnostic capacity is not a timing or SLO promise. No quanta are coalesced to fit it, and overflow remains invalid even when a final record is retained.

The `WorkerQueue` site distinguishes actual queue retirement from a stale observed `queued` phase in an active session. A complete target lifecycle still needs strict framing, bound request/process identity and coherent event order. Those facts alone do not establish whole-capture provenance, peer/recovery behavior, resource closure or native cancellation qualification; the scenario controller must check those separately. A structured record does not itself qualify a model or a serving scenario.

The preserved [initial producer/HTTP CPU evidence](../research/serving-release-20260920/lifecycle-producer-20260921/README.md) remains bound to its original source. Current std-only controls exercise the actual observer and Trace together: frozen chunks in both driver modes, zero/unknown work, future segments and tokenwise tails, ordinary advance/finalization failure, and a simulated client drop during an open quantum. These are not native model or real worker cancellation proofs. Constrained-compiler and dedicated DSv4 lifecycles, normal-completion retirement, and uninstrumented routes remain outside this evidence scope.
