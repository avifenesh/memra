# Request lifecycle diagnostics

`MEMRA_TTFT_TRACE=1` preserves the existing TTFT line and emits bounded `[request-lifecycle]` JSON for the OpenAI completion and chat-completion routes. It is a diagnostic opt-in; normal requests allocate no trace state when disabled.

An optional `x-memra-trace-id` header carries exactly 32 lowercase hexadecimal characters. This key joins a client attempt to the server-generated request ID even when cancellation occurs before admission has produced response headers. It provides no authentication or request authority. Invalid values are not echoed into the log and make the diagnostic history invalid without changing request handling.

Each record includes the process ID, trace ID, ordered sequence number, elapsed nanoseconds from that trace's start, request/model identity, worker-run generation and dispatch route. Capture tooling must additionally bind the process boot/start identity and the actual source and binary. The worker generation is process-local.

The HTTP wrapper distinguishes a dropped pending response, a dropped SSE body, and normal body EOF. Queue overflow and receiver drop are separate worker observations; neither alone proves a client cancellation. The instrumented main-worker queue and active-abort paths record retirement only after the request's owned state and admission/prefix-pin resources are released. Panic and OOM replay do not produce a clean retirement record. The retirement record explicitly names `WorkerQueue` or `ActiveSession` at those two release sites. Historical fixture helpers can record a null site; production retirement hooks require an explicit site. A phase snapshot never supplies the site. Non-SSE response transport is unchanged.

Asynchronous restore parking records the actual `requeued` event. Its trace cannot qualify as a clean single-attempt cancellation, including when a later lost observation quarantines retained resources. Dropping a closed queued request while a matching pending or ready restore exists does not emit `WorkerQueue` retirement: the restore still owns its cache, pin or ticket. The existing restore owner continues its normal polling, expiry and quarantine behavior. A restore owned by another request does not block this request's retirement evidence. This does not add a GPU wait or free pending resources early.

Legacy prime marks record TTFT timing only, including empty-suffix MTP paths. Only an actual nonzero-row quantum starts an observed prime phase; a successful return with known zero remaining chunks finishes it. Unknown remaining work stays unknown. The phase is the last observation, not continuous coverage of uninstrumented code: a stale queued phase cannot prove queue cancellation. The quantum API uses the trace's own clock. Saved-walker and eligible direct plain-prefill call sites observe their actual selected inputs; the existing final carry flush stays inside the last operation. Uninstrumented routes provide no prime-work proof.

Consumers must reject incomplete bindings, invalid ordering, event suppression, and missing final records. At most 8192 ordinary records, one overflow record and one final record are emitted per trace. Every record advertises `ordinary_event_limit`; qualification must fit its preregistered event budget within that limit and retain a complete unsuppressed history. A structured record does not itself qualify a model or a serving scenario.

Current validation includes independent source review, strict production/all-target Clippy, and 799 passing Linux server tests at `aa25e935`, with eight ignored tests. These CPU results do not qualify native serving; the complete cancellation consumer, controller/process/artifact bindings and real model runs remain pending. Constrained-compiler and dedicated DSv4 lifecycles, normal-completion retirement, and unwired quantum paths are not qualified by this change.
