# Kernel inventory

This page maps every `.cu` entry symbol in `crates/memra-engine/cu/` to what it computes, its
types, its arch guard, what selects it, the Rust code that calls it and the gate that pins it. It
is for kernel authors and reviewers. Update the affected rows in the same change that touches a
`.cu` file or an FFI shim (`AGENTS.md`). `tools/kernels-symbol-census.py`, run by
`tools/docs-registry-census.sh` in CI and the pre-push hook, refuses an entry symbol that no row
names. Removed kernels, measurement prose and the per-lane history of this page are in
[history/KERNELS.md](history/KERNELS.md).

## How to read the tables

- **Symbol**: every entry symbol the row covers, each by its exact name; one row may group
  several. An entry symbol is a `__global__` kernel or an `extern "C"` host function of a TU,
  including those in the `cu/` headers it includes and those a macro stamps out. Template kernels
  are written `name<...>`. In static-library rows the `extern "C"` host entries come first, then
  after `kernels` the `__global__` kernels that only those entries launch.
- **Computes**: one sentence ending in the numeric class: bit-identical to a named program, a
  named class (with its record), or a tolerance against an oracle.
- **Types**: weights, activations and output. **Arch**: the guard or the stub that replaces it;
  `any` means every build target.
- **Selected by**: a flag name (contract and default in [FLAGS.md](FLAGS.md)), `default` (the
  calling path has no switch), `sm_100a` or `GB10` (a build- or device-keyed default with no
  switch), `gate-only`, `bench-only` or `test-only`.
- **Caller**: the Rust function that launches it. Fatbin kernels are looked up by name through
  `Engine::func`, which searches the eight modules in build order; `Engine::func_g` resolves from
  the kf8vf8 flash module. Static-library entries are `extern "C"` host launchers declared in the
  FFI module the Caller column names (`src/mmq_ffi.rs`, `src/dsv4_ffi.rs` and others).
- **Gate**: a `kernel-check` cell, an engine test under `tests/`, or a gate binary under `src/bin/`
  (with the gate functions in parentheses when one binary runs several).

Architecture overview: [ARCHITECTURE.md](../ARCHITECTURE.md). The Hopper lane ledger is
[ARCHITECTURE-H100.md](../ARCHITECTURE-H100.md). Decision records: [decisions/](decisions/).

## Build and binding

`build.rs` names every `.cu` file in `cu/`. Which ones compile depends on the build target (stubs
replace three TUs off the `120a` and `100a` families) and on two optional CUTLASS build
variables. The arch table is `src/cuda_arch.rs`.

### Targets, stubs and compile defines

- Targets: `120a` (default), `121a`, `100a`, `90a` and `89`, from `MEMRA_CUDA_ARCH` or the
  `nvidia-smi` compute capability, falling back to `120a`. Source, stub and `-D` choices key on
  the policy family; only the gencode uses the exact target, so `121a` (GB10) compiles the `120a`
  source set. Record: [SM121-SPARK-TARGET.md](decisions/SM121-SPARK-TARGET.md).
- `-DMEMRA_PORTABLE_CUDA=1` on the `89` and `90a` families, `-DMEMRA_HOPPER_MMA=1` on `90a`,
  `-DMEMRA_SM100_TCGEN05=1` on `100a` for `cu/mmq_fp4.cu` and `cu/mmq_fp8_blk.cu`.
  `-DMEMRA_DISABLE_NATIVE_FP4=1` drops the mxf4nvf4 kernel from the `100a` gemm fatbin.
- Stubs (fail-closed twins with the same ABI): outside the `120a` and `100a` families,
  `cu/mmq_fp4_stub.cu`, `cu/mmq_nvfp4_w4a8_stub.cu` and `cu/mmq_fp8_blk_stub.cu` replace the real
  TUs. `cu/fa3_prefill.cu` compiles with `-DMEMRA_FA3_STUB` everywhere except `90a`.
- `-fmad=false`: `cu/dsv4_gpu.cu` (lifted only by the research build variable `MEMRA_DSV4_FMAD=1`),
  `cu/mimo_audio_codec_rvq.cu` and the optional `cu/dsv4_dense_cutlass.cu`. `cu/mla_attn.cu` and
  `cu/tp_ar.cu` keep default contraction.
- Build-time tune and rollback seams (`MEMRA_MMQ_X_*`, `MEMRA_FA_PP_MINBLOCKS`, `MEMRA_IQEXP_K16`
  and others) are in the build-time table of [FLAGS.md](FLAGS.md).
- `DOCS_RS=1` builds empty placeholder fatbins and no archive.
