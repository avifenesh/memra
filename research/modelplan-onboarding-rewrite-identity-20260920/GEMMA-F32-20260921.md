## Cause and repair

Gemma's decode/verify attention consumed only the fused q8 norm pair and passed
an empty F32 fallback into projection dispatch. The requested `MEMRA_FAST=0`
program requires the real F32 operand. Recover it from the still-live residual
and that layer's actual norm with `rms_norm_decode`, which uses the same
1024-thread reduction as the fused norm. Do not reconstruct it from q8 bytes.
Only projections which cannot use q8 receive this operand: a fast sibling keeps
its empty fallback, so it cannot newly enter a raw-activation prefill arm.
Global attention still copies K into V; an unused V weight causes no allocation.

The runtime audit also found Q4 fused projection calls in attention and the
dense FFN which did not check fast eligibility. Those calls now require the
existing per-weight predicate. Finally, the two Gemma verify roots scope out
the prefill crossover at 16+ rows when FAST=0, restoring the previous engine
state on return or error. Fast-mode dispatch and default flags are unchanged.
There is no shared kernel change, registry expansion, admission bypass, or
change to the Qwen selected campaign, oracle, or tolerance.

Actual caller review found that `generate` and `generate_with` could select the
q8-only device-counter twin, including by falling through into the generic
counter branch. FAST=0 now stays on their ordinary host Eager loop. Direct
Gemma counter entry refuses FAST=0 before embedding, KV/output writes or counter
advancement. This does not qualify counter/graph or MoE surfaces. Fast-mode
generator routing remains unchanged.

The independent controller review also found an archive-collision error: an
older `rewrite-receipts.failed.tsv` could leave the live admission index behind.
Failure finalization now reserves a unique hard-link destination without
overwriting older evidence, then removes the live index. Tests retain multiple
older quarantines and confirm the actual qualification loader refuses the
bundle once its live index is removed; `result.json` alone never revokes it.
