# Canonical GDN Eager prerequisite (#542 / #541)

At the Gemma freeze `3c5cb6822d0c0fb22668338ca9de157031062238`, the
Qwen35 dense hybrid plan selected generic `native-eager`, whose operation table
omits `GatedDeltaNet`, `RecurrentState` and `FusedAttentionGate`. MtpSpec eligibility
does not establish the Eager baseline that strict runtime admission requires.

This separate declaration retains `execution_rewrites(&ModelPlan)` as the
canonical entry. Callers select its typed `RewriteSurface::DecodeEager` and
`MtpSpec` rows and retain the emitted ID, implementation, plan hash and operations.
No new public selector, architecture-name grant, or #541 registry fork is needed.

The existing canonical generic walk, when its trunk contains GatedDeltaNet,
selects a dedicated `native-gdn-eager` manifest. Its column declares only the
11 operations of the dense serial GDN/full-attention T1 program. Generic Eager,
fresh-KV, Gemma, graph, prime and speculative columns retain their previous
values. Unsupported MoE, HyperConnections, separate gates and PLE stay blocked.

The actual runtime path is `HybridModel::decode_step_h`: its layer walk dispatches
`Mixer::Linear` to `linear_attn_decode[_pre]`, whose inner path uses the layer's
compiled GDN geometry, resident convolution/recurrent state, GDN scan and gated
RMS/output projection. Full layers use `full_attn_decode` and the compiled fused-Q
attention gate; the loader validates that gate layout before tensor upload.
The dense MLP and serial residual are the same existing T1 walk. No runtime math,
loader, identity, worker, cache or #541 checkout is changed by this declaration.

The captured Qwen3.8-27B header witness compiles to Qwen35, 65 configured layers,
one NextN block, hidden size 5120, vocabulary 248320 and Embedded draft source.
Its plan hash is
`ba7c980ab6201a25c0534493aab7f0fd1d90507f80797c7ad88807a0057464fc`.
The witness contains metadata and one embedding tensor header, no usable model
weights: it is explicitly nonloadable, and proves only manifest selection.
The separately captured full artifact identity is not a header-fixture identity.

CPU controls pin exact operation membership, canonical rather than architecture
selection, excluded mixed programs, unchanged generic/fresh-KV coverage and
receipt separation. Rehashed generic Eager receipts cannot masquerade as the new
implementation; Eager-only receipts do not grant Spec or any other surface.
Actual source review and fresh Eager/MtpSpec native receipts remain required
after the parent selects a coherent source composition. Neither old generic
batteries nor a completed head-upload proof substitutes for those receipts.
