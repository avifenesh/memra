# Standalone mixed FP8 / FP4 arithmetic gate

This is not integrated into the DSV4 engine and carries no model-throughput
or production qualification claim.

CUDA 13.1 compilation for explicit sm_120a emits mixed
`QMMA.SF.16832.F32.E2M1.E4M3.E8` and the reverse E4M3/E2M1 forms.
The [current NVIDIA PTX specification](https://docs.nvidia.com/cuda/parallel-thread-execution/)
allows mixed alternate operands. Repeated type placeholders in the syntax
do not require identical operand types. The signed ModelOpt scale per K16
is a separate constraint from activation dtype support.

The prototype keeps raw FP8 activation codes and E2M1 weight codes. It uses
K16 zero-padded mixed K32 products, then explicit FP32 signed-weight-scale,
per-K128 activation-scale and accumulation steps. This differs from the
engine's f16-MMA reduction class despite introducing no new quantization.

Both target SM120 GPUs passed memcheck and per-expert checks for six experts
at M16/K64 and M4096/K2048. Register-fed operands match the shared/ldmatrix
prototype bitwise, per expert and after aggregation; their own CPU K16
oracle observed zero absolute/relative error. Repeats are bit-stable.
Swapped adjacent scales and removed signs fail the original oracle and
match their separately recomputed mutated oracle. Sanitizer errors: zero.

The register-fed kernel removes shared staging, ldmatrix and barriers. Its
SASS contains the mixed block-scaled MMA and no LDSM. This is a tested
mechanism change, not a performance receipt. Event timings under sanitizer
must not be promoted as speed. A warm post-H2D sequential-expert diagnostic
also lacks the engine's grouped scheduling/cold-weight control.

The gate tolerance is absolute 0.0625 plus relative 1e-5, with observed error
zero. The CPU K16 and scalar-order FP32 oracles themselves differ by up to
0.00732421875 on the full fixture, so this is not proof of identity with the
production f16 program or real-model logits. Those gates remain required.
