Root-cause lane for the prefix-restore tool-call loss. Method, instruments, deviations.
lane/prefix-restore-toolcall, 2026-08-28.

BOX. A rented 2-card RTX PRO 6000 Blackwell Server bench box; identity lives in the private
ops repo, never here. Card 0 serves, card 1 idle. Artifact ~/models/glm53-nvfp4 (NVFP4).
Bench hardware, not a serving box. No production endpoint was touched by this lane.

BINARIES. Both kept on the box for the whole lane so either can be re-measured.
  BASE     sha256 263963b6f0b11834...  the lane-head build already serving when this lane
           opened, byte-identical to the parent lane's NEW arm. Source 0b46351fd.
  PATCHED  sha256 a2b862444416d447...  0b46351fd plus this lane's 60-line fail-closed diff,
           built in ~/memra-lanehead with the tree otherwise clean at that commit.
  BUILD VERIFIED BY CONTENT, NOT BY TIMING (LAW:rebuild-after-checkout-attribution). The
  incremental build reports "Finished in 16.65s", which is exactly the shape that law warns
  about, so the check is `strings` on the binary: the guard's message string is present in
  PATCHED and absent in BASE (grep -c 1 vs 0). `git log -1` is in build-PATCHED.log.
  Two superseded patch revisions (v1 inline guard, v2 predicate without the plain-affinity
  seam) were built and measured; their arms B3 and B4 agreed with B5 and are not reported
  separately beyond their server logs, because only the final diff is the proposal.

ENGINE CONFIGURATION, held constant across every boot except the one variable named:
  MEMRA_CTX=8192, MEMRA_MAX_SESSIONS=4, MEMRA_MOE_RESIDENT=0, MEMRA_MOE_SLOTS=12000,
  MEMRA_ST_PINNED=1, MEMRA_COMPAT=openai, MEMRA_DSA_INDEX_RING=0.
  MEMRA_DSA_INDEX_RING=0 is inherited from the box's existing posture, not chosen here: the
  default is separately broken above ~5k tokens and another lane owns it. Every prompt in
  this lane is under 330 tokens, so that door is not in play; it is stated because a lane
  that inherits a non-default flag must name it.
  DEVIATION FROM THE PARENT LANE, deliberate: MEMRA_PREFIX_CACHE_MB=2000 instead of the
  derived 305 MB. The derived budget holds exactly TWO entries, and the parent lane's
  degeneration cell was confounded by its own arms evicting each other. Six distinct prompts
  at 152.6 MB each need 916 MB. This removes eviction as a variable; it does not create or
  suppress the effect, which also reproduces at the derived budget in the parent lane's
  receipts and in this box's pre-existing serve log.

INSTRUMENTS.
  latentprobe.py  NEW, and the only measurement instrument in the lane. Three probes
                  (tool / recall / bare), two sampler modes, four reps each. Banks the full
                  SSE stream of every request under out-*/ plus a structured JSON, so the
                  claims are re-derivable from bytes rather than from a printed tally.
                  Retention: streams ARE retained this time, unlike the parent cell.
  serve.sh        NEW. PID-VERIFIED stop (GATE:gate-stop-pkill-basename-trap): it resolves
                  /proc/<pid>/exe, refuses anything whose exe is not a memra-server, excludes
                  itself, waits 60 s, and escalates only after re-verifying the SAME pid AND
                  the SAME exe. No pkill anywhere in this lane. The three binaries live in
                  DIFFERENT DIRECTORIES under the SAME basename, per the same law.

PROTOCOL.
  THE ARM SEPARATION IS REP INDEX, NOT PROMPT BYTES. Rep 0 of each cell cold-prefills the
  exact bytes reps 1-3 restore. This is the correction to the parent cell, whose cold arm
  carried a unique nonce prefix: there, "cold vs restored" was confounded with "nonce vs no
  nonce". Here the request bodies are byte-identical within a cell and the server is the
  only thing that changed between reps.
  INTERLEAVING, and why it is not used here. The parent lane interleaved because its arms
  differed in prompt content and box drift could land on one arm. This lane's arms differ
  only by rep index within one continuous cell on one boot, which is a stricter control than
  interleaving would be: interleaving cold and restored here is not possible, because being
  first IS what makes a rep cold. The cross-boot comparison (B1 vs B2 vs B5) is carried by
  a 24-row unanimous split, not by a margin, so drift cannot produce it.
  GREEDY IS THE INSTRUMENT, NEVER THE PRODUCT. Greedy carries the byte-stable signatures
  (the identical refusal string across three restored reps). Every conclusion is ALSO
  carried by the vendor-default sampled arm, which sends no temperature, no top_p, no top_k
  and no seed, because that is the shape customers send.
  reasoning_effort PINNED low in every request (TRAP:reasoning-effort-unpinned-decode-cell).
  A GREEDY LOOP IS AN ARTIFACT, NEVER A FINDING. The restored arms produce textbook loops.
  They are reported as the SHAPE of the failure and never as a defect in their own right,
  and no perf row in this lane comes from a looped generation. There are no perf rows at all.

WHAT IS DELIBERATELY NOT CLAIMED.
  * NO TIMING CLAIM. Every row here is a status, a token count, a tool call or a text match.
    The TTFT numbers in SUMMARY.txt are wall-clock context for the reader, not measurements:
    a restored request is fast because it does no work, which is the bug.
  * No spec-engagement receipt is owed: glm5_next is EAGER-ONLY with no drafter armed
    (boot line in serve-B1.prefix-lines.txt), so K>0 / dspark-acc lines cannot appear. The
    sampled arm's engagement is evidenced instead by its restored reps diverging from each
    other while the greedy reps reproduce byte-for-byte.
  * No product, roster, pricing or context claim. This lane measures an engine defect.
  * The plain-affinity seam in FINDINGS §6 has a CODE-LEVEL finding and NO behavioural
    receipt: the checkpoint declined throughout these cells. Stated rather than implied.

CLOSE-OUT. The box was returned to the posture it was found in: the fail-closed patch was
reverted in ~/memra-lanehead, the lane-head binary rebuilt from the clean tree and verified
to no longer carry the guard string, and the server restarted on it under the original
environment. Lane scratch removed from the box; everything worth keeping is in this
directory.

RECEIPT REDACTION. The banked SSE streams carry the server's `system_fingerprint`, which is
a build fingerprint and does not belong in the public repo. Every occurrence in out-*/*.sse
is replaced with `memra-BUILD-FINGERPRINT-REDACTED`. Nothing else in the streams was
touched: the deltas, tool calls, finish reasons and usage blocks are verbatim. The binary
identities that matter for reproduction are the two sha256 values named above.
