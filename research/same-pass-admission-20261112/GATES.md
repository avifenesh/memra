# Same-pass admission gate runs (memra#1255)

`tools/same-pass-admission-gate.py` through `harness/gate-5090.sh` inside a `gpulock` lease. Card:
one RTX 5090 Laptop GPU (24 GB); the enforced power limit at the start of each run is in its
`gate.log` and was not changed. Model: Qwen3.8-27B NVFP4 + Q5_K, DFlash2 drafter, ctx 32,768,
`MEMRA_PREFIX_CACHE_MB=0`, `MEMRA_REUSE_POOL=0`, `MEMRA_SPEC_GATE_LOW=3`. Two cold prompts of
3,600 prose words (A: 5,772 prompt tokens, B: 5,741), greedy, 96 new tokens. Every gate run is
a single run. Generated by `harness/gate-table.py`; the line indexes count from the pair's fire
in the server log.

| run | binary | gate tool |
|---|---|---|
| `fix5-g6`, `base-g6` | the PR head's code (`fix5`, `94dd52f97f6017be`), base | this PR's head: band from the probed reserve |
| `fix3-g5`, `base-g5` | round 1 (`fix3`, `58f08d69a1b02938`), base | the same |
| `base-g4`, `fix-g4` | base, the code before the review (`fix`, `80d3e8d7e42219d6`) | before the reserve probe: band from the boot floor read as 1,576 MB (the calibration line prints 1,576 MiB = 1,653 MB, the reserve the server applied), so the band was 2,468 to 3,282 MB and the placement at 2,799 MB sat inside it |

The cell: learn each prompt's charge alone on the idle card; start a keeper (a counting run,
greedy) so the worker is in a tick when the pair arrives and `/metrics` is fresh; probe the
reserve the gate applies (B's prompt once more with a 4 s deadline on a reading it cannot fit:
it defers, its defer line names the reserve, and it expires 408 unadmitted); hold a ballast so
effective free (driver free plus pool-cached bytes) beside the keeper is midway between one fit
(`charge_A + reserve`) and two (`charge_A + charge_B + reserve`); fire A and B together.

## Superseded runs of the gate tool (`gates/superseded/`)

Kept for the record; none is evidence for or against the change. Each found a defect in the
tool, fixed in this PR before `base-g4` and `fix-g4`.

| run | binary | what went wrong |
|---|---|---|
| `base-g1` | base | REFUSED: the keeper, then a summary prompt, reached its end of sequence after about 170 tokens, before the pair was placed; the idle worker stopped publishing `/metrics` |
| `base-g2`, `fix-g2` | base, change | Both read V1 PASS and V2 FAIL, wrongly. Beside the keeper the pair was a projected wave of 3, and the default spec band (LOW 2) priced both requests `path=plain`, so their caches were built in `admit`: not the shape under test. The two admissions were also a pass apart (about 150 log lines, decode bursts between them), and the old shape reader counted any two admissions as one pass when no `[prime-yield]` line followed. The current reader reads both runs NOT-PLACED (routes plain, plain) |
| `base-g3`, `fix-g3` | base, change | REFUSED: the reading after the ballast was the one before it. The worker publishes `/metrics` every 32nd tick, so a read one second after the ballast could predate it; the correction step then asked the driver for a second ballast it did not have |
