CELL 3 AS ORIGINALLY AIMED — the PP4 ship-config attempt, and why it produced no ship row.

Boot: the FULL ship env on the PP4 1M posture —
  MEMRA_GLM5_DFLASH=<pinned dflash2>  MEMRA_GLM5_SPEC=1  MEMRA_SPEC_PMIN=0.7  MEMRA_SPEC_STATS=1
  MEMRA_PP_STAGES=4 MEMRA_PP_SPLITS=13,26,39  MEMRA_CTX=1048576

The boot said everything an operator would want to see:

      spec-admission=on
  [spec-k] automatic table: prompt<1024 -> K=3; cold-long -> K=3; ...

And then the verify walk NEVER RAN:
  [glm5-acc] lines .................... 0
  "verify walk BATCHED per layer" ..... 0
  [glm5-vrows] ........................ 0
  PMIN=0.700 .......................... 0
  door T/X/K/W "engaged" .............. 0 each
  usage.spec block on the response .... ABSENT
  decode at 16k ....................... 23.34 tok/s == the plain boot's 23.34

THE REFUSAL IS SILENT. Nothing in the log says spec was declined for this placement. A generic
tok/s probe would have concluded "spec is disappointing at depth" and a serving decision could
have been made on it. Only an engagement gate that DEMANDS the announces catches this — which
is exactly the 2026-08-25 DE DFlash2 shape that produced the never-serve-greedy /
verify-with-a-spec-engagement-receipt law.

Root cause (worker.rs):
    fn glm5_sharded_placement_admits(fence_stages, step_tp, step_ep) -> bool {
        (2..=3).contains(&fence_stages) && !tp_set(step_tp) && !tp_set(step_ep)
    }
Its own doc comment states the reason: the verify-walk ppN twin, the per-stage rollback and the
last-stage MTP chain are red-proven by glm5-spec-ppn-gate at stages=2 and stages=3 only, and
"a stage count outside that set has NO gate receipt and refuses ... fail-closed is the default,
extended deliberately, never inferred." That is correct and deliberate. It simply collides with
1M, because the only demonstrated 1M config is PP4.

Two wrong answers were eliminated FIRST, by measurement, before the code was trusted
(receipts/c3diag/):
  * MEMRA_REUSE_POOL=0 — an addition THIS WINDOW had made for a greedy+vendor 1M pair.
    Reverting it to the default changed nothing.
  * auto-K choosing K=0 at concurrency 1. An operator pin MEMRA_SPEC_K=3 was accepted
    ("[spec-k] operator pin K=3: automatic placement/concurrency/prompt policy and automatic
    demotion disabled") and STILL nothing engaged.
Then cell 3a turned the code reading into a one-variable A/B — see receipts/c3a-ppab/.

Follow-up this earns: make the refusal LOUD (one line naming the stage count and the admitted
range), and extend glm5-spec-ppn-gate to stages=4 so 1M and spec can compose at all.
