## Training program (what we replicate)

- Entry: `specforge train -c <yaml>`, `training.strategy: dspark`. **No qwen3.8 config upstream
  yet** — drafter geometry comes from RadixArk's public config.json: qwen3-class, 5 full-attn
  layers, hidden 5120, 40q/8kv hd128, intermediate 10240, vocab 248320, block_size 7,
  taps [4,16,28,40,52], markov vanilla rank 256, confidence head on (alpha 1.0),
  mask_token_id 248077, max_pos 262144, explicit full yarn rope (factor 32, orig 8192, theta 1e7).
- Loss defaults: CE 0.1 + L1 0.9 + conf 1.0, loss_decay_gamma 4.0, num_anchors 512.
  27B recipe: lr 6e-4, warmup 0.04, global batch 512, 10 epochs.
- **Disaggregated online mode is mandatory** (offline hidden cache ≈ 60 KiB/token → tens of TB).
  Patched SGLang 0.5.14 capture server streams tap hiddens via Mooncake; trainer never loads the
  target trunk — only its BF16 embed + lm_head (verified BF16 in the FP8 checkpoint header).
- **FP8 target trains as-is** (capture is server-side; LongCat-FP8 in-tree precedent). Training
  against the FP8-served target = matched serving distribution.
- Hybrid/GDN (Qwen3.8 = 48 GDN + 16 full-attn): capture server takes
  `--mamba-scheduler-strategy extra_buffer`; unique extra_key per sample forces full prefill (no
  cache contamination). No upstream tap-layer guidance for hybrids; taps read the residual stream.
- Export: `specforge export --to hf --embedding-source <target>` then
  `scripts/gates/normalize_dflash_export.py` (arch → `Qwen3DSparkModel`). GOTCHA on record: an
  exported drafter config inheriting the TARGET's rope (partial_rotary 0.25/mrope) collapsed
  acceptance to ~1% — drafter rope must stay explicit full-dim yarn.

## Eval/serving pins

- SGLang >= v0.5.16 has DSPARK (PR #30261, commit 6cc9352d); prefer **>= v0.5.17 / recent main**
  (Qwen3.8-27B cookbook landed on main 2026-08-14). RadixArk's exact pin unrecoverable.
- Serve: `--speculative-algorithm DSPARK --speculative-draft-model-path <draft>
  --speculative-dspark-block-size 7 --speculative-draft-model-quantization unquant
  --mamba-scheduler-strategy extra_buffer --attention-backend fa3`.
- Acceptance eval: `python -m dflash.benchmark --backend sglang` (z-lab path RadixArk used;
  spec_accept_length = completion_tokens / spec_verify_ct) + `specforge benchmark`; serving gate:
  `scripts/gates/run_dflash_chat_serving_gate.py`.

## Cost/time anchors

- RadixArk run ≈ epoch_2_step_4166 @ batch 512 ≈ 2.1M samples. Agent estimate: ~33-50 h on
  8x H100 ≈ $3-5K OD. No published wall-clock upstream.
- **Warm-start is the dominant cost lever**: community data point (satgeze card) — 27B target,
  12K samples, 3 epochs, **~5.5 h on ONE RTX PRO 6000 96GB**, warm-started from a z-lab DFlash
  head → accept ~5.4; cold start at that scale only ~1.8. z-lab heads exist for Qwen3.6, not 3.8;
  warm-start compat (vocab 248320 / hidden 5120 / taps) is CHEAP TO TEST and could collapse the
  whole training to hours on the interim 2-card box (GPU0 capture + GPU1 trainer).
- Throughput knobs (Domino study, 8xH200): repeat server_urls per producer, CLONE_ON_FETCH=0,
  LOADER_PREFETCH=2, capture --mem-fraction-static 0.5; 28.8 -> 50.1 samples/s.
