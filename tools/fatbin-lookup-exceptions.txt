# Declared arch-conditional kernel lookups, for tools/fatbin-lookup-census.py.
#
# FORMAT:  <arch> <kernel_symbol>   # why this arch legitimately lacks it, and what guards the
#                                   # call site so Engine::func is never reached for it
#
# An entry here says: "this kernel is absent from this arch's fatbins ON PURPOSE, and the Rust
# call site is guarded so the lookup never happens." It is NOT a way to silence a panic. If the
# call site is not guarded, the fix is to guard it — not to add a line here.
#
# WHY EVERY LINE CARRIES ITS REASON. The census is NAME-LEVEL: it greps `.func("x")` out of the
# Rust sources with no notion of reachability, so it reports lookups that are correctly
# unreachable. That over-approximation is deliberate (no false negatives), and this file is where
# the reachability argument gets written down. A bare symbol list would be worthless — it would
# record that someone once decided something was fine, not why. That is exactly the class of thing
# a 75-name grandfather list was deleted over on 2026-08-23: all 75 of its entries had gone dead
# and nothing noticed, because no entry said what it was for.
#
# I got this wrong in the other direction first, which is why the reasons are this explicit. A
# grep for `portable_mma_gated` inside src/hybrid_forward.rs finds nothing, and I reported that as
# "the batched GDN path is unguarded" — a published claim that sm_89 assets could panic. The guard
# is ONE CALL DEEP (`gdn_mma_enabled()`), and a name-level check is not a reachability check.
#
# THIS FILE HAS ITS OWN DRIFT CHECK. The census refuses when an entry rots in either direction:
# the symbol is now PRESENT for that arch (grant dead), or the symbol is no longer looked up
# anywhere (renamed/deleted, so the grant now covers whatever next takes the name).
#
# =============================================================================================
# sm_89 (portable Ada) — the GDN varlen + mma chain.

# SHARED REASON for the 17 GDN entries below. cu/hybrid.cu:1575-2238 is
# `#if !defined(MEMRA_PORTABLE_CUDA) || defined(MEMRA_HOPPER_MMA)` with no #else, so sm_89 does
# not get these. Every one of them is unreachable on sm_89, traced call site by call site:
#
#   * the 14 `*_vl` kernels are launched only by the five `*_vl8` wrappers, and each wrapper has
#     EXACTLY ONE caller — all inside the `use_vl` block at src/hybrid_forward.rs:4058-4099.
#     `use_vl` (:3937) requires `e.gdn_mma_enabled(c)`, and gdn_mma_enabled (src/lib.rs:24097)
#     begins with `!portable_mma_gated()`. On sm_89 `use_vl` is false and the function returns
#     early to linear_attn_prime_core_pad_view, which uses the generic fallback. Verified by
#     enumerating callers of all five wrappers: one each, no others.
#   * gdn_chunk_state_mma / gdn_chunk_output_mma (src/lib.rs:24861, :24889) sit under `gdn_mma`
#     (:24797), which is `!portable_mma_gated() && …`.
#   * gdn_chunk_attn_f32 (src/lib.rs:23969) sits under `c <= 64 && !portable_mma_gated()` (:23967)
#     — the guard the other two mirror, and the one docs/FLAGS.md describes when it says sm_89
